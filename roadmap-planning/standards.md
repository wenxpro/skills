# 演进规划规范（个人/团队风格标准）

本仓库（cheese/pi-agent 项目文档集）约定如下，其他团队可整体替换。

## 分期定义

- **MVP**：验证内核（产品需求文档 4.1，验收 M1-M20）
- **V1**：产品化（PRD 4.2：TUI 完整、扩展系统、RPC、认证子系统）
- **V2**：订阅化（PRD 4.3：云端会话同步、团队共享执行环境、统一策略）
- **包内优先级 P0/P1**：标注在各包 DESIGN.md，属包级排序，与 MVP/V1/V2 里程碑分期并存

## 验收项来源

- 八篇论证文档（内核闭环、上下文装配、模型与认证、扩展生态、多形态前端、会话数据与遥测、多Agent编排、评测体系）末尾的验证清单，共 71 条，可按里程碑拆解
- 设计总纲第五部分的自检项
- 归组后形成编号验收（M1-M20 等），定义在 PRD 第六节

## 落点约定

- 生态/竞品观察的落点 → 设计总纲 1.5 观察条目（不另立文档）
- 机制方向落点 → 对应论证文档（如「上下文装配 V1 方向」）
- 包内能力 → 包 DESIGN.md
- 规划结论 → PRD 第四/六节与 README「下一步」

## 排序依据

- 依赖链是硬约束：被依赖项先实现（本项目例：Esc 中断 → runLoop abort 协议 → 触发式规则注入）
- 同级内排序：体验落差 > 机制层先于策略层
- 订阅项必须满足「本地给不了」条件（付费墙规则：云端同步、团队共享执行环境、统一策略——本地能做的功能不进订阅范围）
