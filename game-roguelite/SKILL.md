# Roguelite 单局与构筑

目标：让每局有**节奏、选择、变化**，而不是把随机升级堆成一条数值曲线。

本 skill 负责单局结构、构筑轴、奖励/进化、内容池、局内外进度；数值平衡用 `game-systems-balance`，关卡用 `level-encounter-design`，战斗模型用 `game-combat-model`。

## 何时使用

- 设计 roguelite/roguelike 的单局流程、升级三选一、构筑、进化
- 需要内容表、卡池权重、奖励节奏、确定性种子
- 排查「每局都拿同一套」「升级没选择」「后期只剩数值」「局外成长压过局内」

不适用：

- 数值/经济/难度平衡 → `game-systems-balance`
- 关卡/遭遇布局 → `level-encounter-design`
- 攻击/伤害/克制模型 → `game-combat-model`
- 剧情/对白 → `narrative-docs`

## 行为

参考型 skill，无主动打断。用户要求设计/审计单局与构筑时使用。

## 核心规则

### 1. 先定单局形状

- 目标时长、局数节奏、失败/胜利条件。
- 开局（build 起点）→ 成长（奖励）→ 峰值（精英/Boss）→ 收束（终局）。
- 每局至少有一个「我变强了」和一个「我做了取舍」的时刻。
- 单局太长会疲劳，太短没有构筑空间；用试玩/时长分布验证。

### 2. 构筑轴至少两条

- 可用轴：伤害类型、射程、节奏、生存、召唤、控制、资源、风险。
- 两条轴要产生不同打法，不只是「伤害 + 暴击」。
- 选项之间要有取舍；纯上位替代会消灭选择。
- 构筑要有可识别的流派/标签，但不要逼玩家背最优解。

### 3. 奖励节奏

- 升级/奖励频率、稀有度、保底、重随规则。
- 每次奖励至少有一个「当前有用」和一个「长期投资」。
- 避免空升级/无效奖励；满级/满槽要有转化。
- 奖励之间要有协同，但不要只有唯一组合。
- 失败也要有学习/进度反馈，不是纯惩罚。

### 4. 内容池

- 卡/物品/武器/进化一张表；权重、前置、互斥、上限。
- 池子随进度/角色/学说变化；变化要可解释。
- 确定性种子；同种子可复现；随机不产生不可能/无解组合。
- 内容表是单一事实源；代码不写死内容。
- 池子规模服务变化；不要用海量低质选项填充。

### 5. 进化/转化

- 条件（等级/组合/事件）、分支、一次性/可重复。
- 进化要改变玩法，不只是数值放大。
- 进化前后要可读；玩家能理解触发条件。
- 分支要能在单局内被识别，不要藏在数据里。
- 进化不是必选；没有进化也能赢，但有不同路线。

### 6. 局内 vs 局外进度

- 局内：本局构筑、资源、等级、地图。
- 局外：解锁、图鉴、难度、起始选项、元货币。
- 局外成长不能压过局内选择；否则新手靠刷、老手无挑战。
- 失败也要给局外进度，但不要用进度掩盖局内设计问题。
- 明确哪些东西跨局保留、哪些重置。

### 7. 随机与公平

- 种子、池权重、保底、重随、ban/pick。
- 不产生必死/无解局；极端组合有兜底。
- 随机要可解释：玩家知道为什么出现这个选项。
- 难度档可以改压力，但不要偷偷改规则。
- 记录每局种子/构筑/结果，便于复现。

### 8. 失败与重开

- 死亡→重开时间短；保留学习信息。
- 单局结算显示构筑、关键选择、死因、Boss TTK。
- 失败不是「再来一次」的空洞重复；要有新信息/新选择。
- 重开流程不阻塞；跳过过场。

### 9. 证据

- 种子化跑批：胜率、时长、构筑分布、奖励选择率。
- 构筑矩阵：不同流派/组合的可行性。
- 内容表覆盖：每个选项被选/被跳过/是否有效。
- 试玩：是否想再来、是否觉得有选择。
- 静态截图不能证明单局节奏。

## 检查清单

- [ ] 单局时长/节奏/胜负条件明确
- [ ] 至少两条构筑轴，选项有真实取舍
- [ ] 奖励频率/稀有度/保底/重随明确
- [ ] 内容表是单一事实源，有权重/前置/互斥
- [ ] 确定性种子，极端组合有兜底
- [ ] 进化改变玩法，不只是数值
- [ ] 局内/局外进度边界清楚，局外不压过局内
- [ ] 失败有学习信息，重开短
- [ ] 有种子化跑批/构筑矩阵/内容覆盖证据
- [ ] 真人试玩验证「想再来」，不是只看胜率

## 输出

- 单局结构：`references/run-structure.md`
- 构筑与内容池：`references/build-and-pool.md`
- 单局规格模板：`templates/run-spec.md`

## 反模式

- 每局都拿同一套最优解
- 升级只有数值上位替代
- 内容池很大但大部分是填充
- 局外成长压过局内选择
- 随机产生无解/必死局
- 进化只是伤害放大
- 失败没有新信息，只是重复
- 用胜率证明「好玩」

## 交接

- 数值/经济/难度平衡 → `game-systems-balance`
- 关卡/遭遇 → `level-encounter-design`
- 战斗模型/攻击时间轴 → `game-combat-model`
- 单局反馈/音效/震屏 → `game-feel`
- 内容表/验收 → `game-docs`
- 验证计划/证据 → `validation-design`

## 边界

- 不写具体项目的时长、角色数、武器数、卡池数值
- 不替代平衡、关卡、战斗模型
- 不把「随机」当内容；随机只是重玩性的一个来源
- 局外进度不能用来掩盖局内设计问题
