# LLM 调用集成

把概率模型接入确定性系统，核心风险不是「模型不够强」，而是**把模型输出当成了可靠输入**：推理过程被当成答案、约束没有生效、超时后旧响应才到、降级发生了却没人看见。

本 skill 的顺序是：**先验证模型行为，再定义适配边界，最后用失败路径和回放证明系统可靠。**

> 通用层只写与供应商无关的规则。领域约定在 [`standards.md`](standards.md)；验证步骤在 [`references/probe-checklist.md`](references/probe-checklist.md)；故障速查在 [`references/failure-modes.md`](references/failure-modes.md)；具体运行时、模型、字段与命令在 [`examples/`](examples/)；配置模板在 [`templates/model-profile.json`](templates/model-profile.json)。

## 何时使用

- 把本地或云端模型接入确定性系统（游戏、工具、自动化流程）
- 需要受约束输出（枚举、固定结构），而不是自由文本
- 排查空答案、推理占用预算、超时、非法动作、模型切换
- 设计高频跑批、降级、回放与模型对比

不适用：prompt 文案调优；模型训练/微调；provider 账号与计费；只查一个 API 参数怎么用；泛化的模型生态/竞品调研（用 `topic-research`）。

## 核心原则

1. **先验证行为，再接业务。** 用真实约束直接请求模型，确认最终答案、推理过程、结束原因和延迟，再写适配层。
2. **模型是配置，不是分支。** 用模型档注册表 + 一个活动档；代码不按模型名分支。
3. **受约束输出，语义再校验。** 输出结构由允许集合生成；解析成功后仍要校验语义，不能只信格式。
4. **最终答案与推理过程分离。** 推理过程不是答案；没有最终答案就是失败。
5. **失败必须降级，且可见。** 超时、格式失败、语义非法、模型不可用，都要走确定性降级，并在观测里单独计数。
6. **一次运行一个模型档，记录来源。** 记录档位 id、能力、提示与约束指纹、用量、结束原因、延迟。

## 操作顺序

1. 定义决策面
2. 定义模型档
3. 验证模型行为
4. 接适配层
5. 覆盖失败路径
6. 回放与验证

## 第一步：定义决策面

先写清楚，不写代码：

| 问题 | 产出 |
|---|---|
| 决策点在哪里、多久一次 | 稀疏决策点清单；逐帧请求不适合模型 |
| 输入是什么、输出必须是什么 | 紧凑状态 + 候选标识；输出只含选择结果 |
| 谁最终裁决合法性 | 业务侧是最终权威，适配层只做预校验 |
| 单次和整体预算 | 超时、输出预算、重试次数、降级动作 |
| 失败后怎么办 | 确定性降级；本流程必须能跑完 |
| 记录哪些字段 | 决策、选择、校验结果、用量、延迟、模型档 |
| 哪些字段不参与对比 | 延迟、用量、时间戳、原始响应 |

## 第二步：定义模型档

- **区分用途**：高频跑优先低延迟、低推理；内容验证可以接受更高延迟和推理。
- **区分训练形态**：instruction 型不等于 reasoning 型；同系列不同版本可能行为完全不同。
- **先算总账**：权重、上下文、缓存、运行时开销一起算，不只看文件大小。
- **能力声明**：受约束输出、随机种子、多模态、上下文长度；启动时校验，不满足就失败。
- **实测优先**：新模型不等于适合；先看是否能稳定产出受约束结果。
- **模型档是数据**：一个实体、一个注册表、一个活动档；换模型只改配置。

具体的候选、量化、字段与延迟记录放 `examples/`，不写进通用层。

## 第三步：验证模型行为

用真实输入和真实约束直接请求模型，不经过业务代码。

检查：

- 传输成功，且响应体是可解析的结构
- **最终答案**非空
- **推理过程**是否独立、是否吃掉了输出预算
- **结束原因**是否表示被截断
- 选择结果是否在允许集合内
- 冷启动与热启动各测一次；记录延迟分布

**通过条件**：没有最终答案、输出被截断、选择非法、响应不可解析，任一出现就不要接线。

详细步骤见 `references/probe-checklist.md`；具体字段名与请求示例见 `examples/`。

## 第四步：接适配层

- **模型档注册表**：id、传输方式、端点、模型、能力、采样、预算；一个活动档。
- **未知档或不满足能力**：启动前失败，不静默回退到另一个模型。
- **提示**：稳定前缀；只放当前决策需要的状态和候选；候选标识与约束枚举同源。
- **输出**：只要求最小结果；输出预算只够结构本身；不要求解释。
- **校验**：解析 → 结构 → 允许集合 → 业务最终裁决；失败重试一次，修复提示里带错误，不无限重试。
- **传输**：单飞行；请求有超时；超时先标记结束再取消；忽略结束后的迟到响应。
- **记录**：每次决策一条；一次运行一个隔离位置；记录档位、指纹、用量、结束原因、延迟；原始响应可选。

配置形状见 `templates/model-profile.json`。

## 第五步：覆盖失败路径

至少覆盖：

| 场景 | 期望 |
|---|---|
| 模型或端点不可用 | 启动前或首次请求失败；走整体降级，观测可见 |
| 没有最终答案 / 只有推理 | 不当作成功；按推理占用或截断处理 |
| 输出被预算截断 | 增加预算或降低推理；不能静默接受半截结果 |
| 约束不生效 / 结构非法 | 修复重试一次；仍失败则降级 |
| 选择结果语义非法 | 拒绝并记录；不修改业务状态 |
| 超时后迟到响应 | 先标记结束再取消；迟到响应丢弃 |
| 同步失败与异步回调双处理 | 只保留一条失败路径，避免降级计数翻倍 |
| 通道断开 / 重连 | 当前决策降级；会话状态可见 |
| 同一位置重跑导致记录追加 | 每次运行前隔离本次产物 |
| 模型档拼写错误 | 启动前失败，不静默使用默认模型 |
| 冷启动异常慢 | 用热启动延迟做选型；冷启动不计入分布 |
| 关闭推理的开关看似生效、换输入又失效 | 不依赖单一开关；按最坏情况给预算或换模型 |

详细症状与修法见 `references/failure-modes.md`。

## 第六步：回放与验证

- 记录选择序列；回放不加载模型，按 `(运行种子, 决策序号, 观察指纹)` 匹配。
- 严格模式遇到指纹不一致立即停；宽松模式继续但标记偏离与过期。
- 验证矩阵：
  1. 模型行为验证（真实约束）
  2. 适配层单元测试（结构/允许集合/非法选择）
  3. 完整短流程（零降级 / 零非法动作）
  4. 失败注入（超时、空答案、模型不可用、断开）
  5. 回放一致性（选择/结果/关键指标）
  6. 正常模式回归（不启用模型时行为不变）

## 反模式

- 先写业务代码，最后才试模型。
- 按模型名猜能力；把「新」当「适合」。
- 用 reasoning 模型做高频逐帧或高频决策。
- 只看传输成功，不检查最终答案是否为空。
- 用自由文本加正则解析选择结果。
- 重试没有上限，或降级静默发生。
- 超时后取消，却把迟到响应当成新响应。
- 同一位置追加记录，重跑后数量翻倍。
- 把凭据、完整端点或原始提示写进观测。
- 服务绑定到所有网卡，或把模型端点暴露到局域网。

## 主动行为

无主动行为。只在被调用时执行；不打断用户，不主动建议换模型，除非验证结果触发上面的条件。

## 边界

- 不训练、不微调、不做量化。
- 不写具体 prompt 文案；只规定结构与验证。
- 不处理 provider 账号、计费、配额申请。
- 不替代项目验收；回放通过不等于内容结论成立。
