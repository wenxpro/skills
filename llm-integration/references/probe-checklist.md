# 模型行为验证清单

> 目标：在写业务适配层之前，确认模型能稳定产出满足约束的结果。任何一项不通过，先解决模型/参数，不要接线。

## 前置

- 端点可用，模型已加载；记录准确的模型标识、能力、上下文与预算。
- 端点只绑定本机回环；验证阶段不暴露到局域网。
- 准备一条真实决策输入：包含当前状态、候选标识、允许集合。

## 步骤

1. **确认端点与模型**：模型标识与预期一致；能力声明与实际一致。
2. **冷启动请求**：用真实输入和真实约束发一次；记录延迟。
3. **热启动请求**：同一请求再发数次；记录延迟分布。
4. **检查最终答案**：必须非空，且能被解析为预期结构。
5. **检查推理过程**：推理是否独立；是否占用了输出预算。
6. **检查结束原因**：是否表示被截断；截断不能当作成功。
7. **检查语义**：返回的选择是否在允许集合内。
8. **检查响应体**：传输成功不等于结构可解析；不可解析时记录状态、长度与摘要。
9. **记录**：模型标识、能力、采样、预算、提示/约束指纹、延迟、用量、结束原因。

## 判定

| 现象 | 判定 |
|---|---|
| 最终答案非空、结构合法、选择在允许集合、未被截断 | 通过 |
| 没有最终答案、只有推理 | 不通过；推理占用或截断 |
| 结束原因表示截断 | 不通过；增加预算或降低推理 |
| 响应体不可解析 | 不通过；先查传输与协议 |
| 选择不在允许集合 | 不通过；约束或候选不同源 |
| 热启动延迟超出任务预算 | 不通过；换更小/更低推理的模型 |

## 验证后只做一件事

把结果写进模型档：标识、能力、预算、实测延迟。不要在业务代码里凭记忆写模型名或参数。

具体字段名、请求样例与运行时命令见 `examples/`。
