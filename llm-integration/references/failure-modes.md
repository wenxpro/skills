# LLM 调用故障速查

> 症状 → 可能原因 → 检查 → 修法。与供应商无关；具体字段名与表现见 `examples/`。

| 症状 | 可能原因 | 检查 | 修法 |
|---|---|---|---|
| 没有最终答案，只有推理 | 模型在推理；输出预算被推理吃光 | 推理用量、结束原因 | 换低推理模型；或给足预算/降低推理 |
| 输出被截断，结构不完整 | 输出预算太小；推理占用 | 用量分布、结束原因 | 增加预算；缩短输入；降低推理 |
| 传输成功，但响应体不可解析 | 分块/压缩/代理/流式未关闭 | 状态、长度、摘要；是否非流式 | 关闭流式；换可靠客户端；记录原始响应 |
| 约束已给，结构仍非法 | 提供方未执行约束；模型能力不足 | 用同一约束直接验证 | 修复重试一次；仍失败则降级；换模型 |
| 结构合法，但选择语义非法 | 枚举与允许集合不同源；缓存过期 | 对比约束枚举与当前允许集合 | 约束从允许集合生成；解析后再次校验 |
| 超时后降级，稍后又有响应 | 取消与回调竞态 | 日志时间线；降级是否重复计数 | 超时先标记结束再取消；迟到响应丢弃 |
| 一次失败导致降级计数翻倍 | 同步失败又触发异步回调 | 失败路径数量 | 同步失败只返回值，不再发完成事件 |
| 同一位置重跑，记录数量翻倍 | 复用输出位置且追加写 | 记录数量与决策数量 | 每次运行前隔离本次产物 |
| 通道收不到消息或发错对象 | 传输层路由问题；单客户端未限制 | 发送者标识、连接状态、消息计数 | 用可靠的传输实现；单客户端；发送前校验鉴权 |
| 选了某档，实际跑了另一个模型 | 未知档静默回退默认值 | 启动日志的档位 id | 未知档启动前失败；不静默回退 |
| 模型不可用，整体卡住 | 没有超时或降级 | 端点与加载状态 | 启动前验证；失败则整体降级 |
| 回放结果不一致，但没人发现 | 指纹失配被静默忽略 | 偏离/过期字段 | 严格模式停；宽松模式标记，不参与对比 |
| 第一次请求异常慢 | 冷启动、加载、缓存未命中 | 冷/热两次延迟 | 用热启动延迟选型；冷启动不计入分布 |
| 关闭推理的开关看似生效，换输入又失效 | 开关只是软提示；实现不一致 | 不同输入的推理用量 | 不依赖单一开关；按最坏情况给预算或换模型 |

## 排查顺序

1. 端点是否可达、模型是否加载
2. 用真实约束直接验证，不经过业务代码
3. 看最终答案、推理、结束原因、用量
4. 再看适配层的解析、校验、重试、降级
5. 最后看业务状态与回放

先怀疑模型行为，再怀疑业务代码；但不要把「模型能返回」当成「业务接线正确」。
