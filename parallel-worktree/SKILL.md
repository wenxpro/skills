# 并行工作树

目标：让多个会话同时改同一个仓库时，工作目录、分支和写者边界清楚。合并的是分支，不是 worktree 目录。

## 何时使用

- 多个会话要同时写同一个仓库
- 长任务、实验分支、两套方案对比
- 主工作区需要保持干净
- 一个会话需要独立上下文，不互相切分支
- 需要判断该顺序做、开分支还是开 worktree

不适用：

- 单会话顺序开发 → 当前分支
- 只读探索 → 主工作区即可
- 提交信息与提交历史 → `git-commit`
- 代码审查 → `code-review`
- 任务交接 → `session-handoff`

## 核心模型

- worktree 是同一个仓库的另一个工作目录；共享对象库、分支和提交，不共享工作区、暂存区和 HEAD。
- **一个 worktree 一个分支一个写者。** 同一个分支不能同时检出到两个 worktree。
- **合并的是分支，不是 worktree。** 不要尝试“合并两个目录”。
- 主工作区默认留在 `main`；特性工作区使用短分支。
- 只读会话可以共享主工作区；写会话必须独立 worktree。

常见误解：

| 误解 | 实际 |
|---|---|
| worktree 之间会实时冲突 | 编辑阶段各自独立，不会互相覆盖 |
| 合并 worktree | 合并分支；冲突发生在 merge/rebase 时 |
| 一个分支可以多 worktree 同时写 | Git 默认不允许；需要各分支独立 |
| worktree 隔离一切 | 端口、数据库、外部服务、共享缓存不隔离 |

## 选择隔离方式

| 场景 | 做法 |
|---|---|
| 单会话顺序开发 | 当前分支 |
| 只读探索 | 主工作区 |
| 并行写同一仓库 | 独立 worktree + 独立分支 |
| 大实验/不同依赖 | 独立 clone |
| 同一功能多会话 | 功能集成分支 + 子分支 |

## 创建流程

1. **确认工作区干净**：有未提交改动先提交、暂存或询问用户；不要直接切走。
2. **同步主分支**：先拉取/更新，避免从过期基线开分支。
3. **建短分支**：`feat/<slug>`、`fix/<slug>`、`docs/<slug>`、`exp/<slug>`；一个分支一件事。
4. **创建 worktree**：优先使用 OpenCode 的 `worktree_create`；不可用时用 `git worktree add`。路径放在仓库外或已忽略的目录。
5. **移动会话**：需要把当前会话作为主工作目录时，用 `session_move`；否则明确切换到该目录。
6. **记录边界**：分支、worktree 路径、owner、目标、验证命令写进 handoff 或任务记录。

## 并行规则

- 一个 worktree 只允许一个写者；其他会话只读。
- 不同会话尽量改不同模块/文件；共享接口、配置、内容表先冻结或指定 owner。
- 不在同一分支上开两个写会话；需要协作时用子分支 + 集成分支。
- 频繁同步主分支，保持短分支；不要长期漂移。
- 不把依赖目录、构建产物、日志、本机配置带进提交。
- 只读会话可以看 `main`，但不要改文件或切分支。

## 合并

合并前：

1. 在特性 worktree 内提交并跑检查。
2. 同步主分支；需要时 rebase/merge `main`。
3. 走 `code-review`；高风险改动不得跳过。
4. 确认没有未提交文件和未跟踪的临时产物。

合并方式：

| 方式 | 适合 | 做法 |
|---|---|---|
| 依次合回 main | 分支少、文件不重叠 | 主工作区 `merge --no-ff` 每个分支 |
| integration 分支 | 多分支同批功能 | 先合入 `integration/<topic>`，整体测试后再回 main |
| rebase + fast-forward | 单人、追求线性历史 | 特性分支 rebase main，再 ff 合并 |
| PR/MR | 需要评审/记录 | push 分支，走远程合并 |

规则：

- 冲突在**合并分支时**解决，不在 worktree 之间同步目录。
- 机械冲突解决后必须跑检查；语义冲突停下来问用户。
- 不 rebase 共享的 `main`；不 force push 共享分支。
- 合并后主工作区复跑检查，确认集成分支结果一致。

## 清理

- 合并后删除 worktree 和已合并分支；用 `worktree_remove` 或 `git worktree remove`，再 `git branch -d`。
- 未提交、未合并的 worktree 不自动删。
- 删除有未提交改动的 worktree 必须先问用户；不要默认 `--force`。
- 定期 `git worktree prune` 清理失效记录。

## 输出要求

一次并行工作区处理，至少说明：

1. 为什么需要 worktree，而不是当前分支
2. 分支名、worktree 位置、owner
3. 合并顺序与策略
4. 检查/审查结果
5. 冲突、未决项和风险
6. worktree/分支清理状态

## 反模式

- 两个会话在同一个 worktree 写。
- 同一个分支强开多个 worktree 写。
- 把 worktree 当成分支合并工具。
- 在 `main` 上直接并行写。
- 长分支长期不同步，最后一次性解决大量冲突。
- 自动解决语义冲突，不跑检查就合并。
- 删 worktree 前不检查未提交改动。
- 把依赖、构建产物、日志、本机配置带进提交。
