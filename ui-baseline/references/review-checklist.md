# UI 评审检查表

> 每条给出「通过 / 有条件通过 / 否决」；否决写具体位置与修正建议。截图是证据，不是装饰。

## 1. 基线与一致性

- [ ] 只使用语义 token；View 中没有硬编码颜色、字号、圆角、间距
- [ ] 字体层级与间距节奏一致
- [ ] 组件变体命名一致，没有同一组件多套实现
- [ ] 浅色/深色来自同一套语义 token
- [ ] 图标风格、线宽、圆角一致

## 2. 屏幕与流程

- [ ] 每个屏幕只有一个主动作
- [ ] 入口、退出、返回路径明确
- [ ] 空 / 加载 / 错误 / 成功状态齐全
- [ ] 键盘/安全区/Sheet 不遮挡主操作
- [ ] 删除/重置/覆盖有二次确认
- [ ] 可逆操作有撤销或恢复路径

## 3. 组件状态

- [ ] default / pressed / disabled / loading / error 都有定义
- [ ] 禁用态与加载态的文案/行为清楚
- [ ] 长文本、空值、超长名称有处理
- [ ] 列表/网格在不同宽度不裁切
- [ ] 触控目标达到平台最小尺寸

## 4. 无障碍

- [ ] 对比度达标（正文/大字号/图形）
- [ ] 动态字号/缩放最大档主路径可完成
- [ ] 屏幕阅读器可完成主路径，标签与顺序合理
- [ ] 状态不只靠颜色
- [ ] Reduce Motion / Reduce Transparency 生效
- [ ] 表单错误可定位、可朗读

## 5. 文案

- [ ] 文案具体、直接，不夸张
- [ ] 不暗示自动化或系统能力
- [ ] 错误说明原因与下一步
- [ ] 破坏性操作说明后果
- [ ] 中英文/数字格式一致

## 6. 证据

- [ ] 浅色截图
- [ ] 深色截图
- [ ] 关键状态截图（空/错误/加载/AX）
- [ ] 关键尺寸截图（最小/标准/最大）
- [ ] 截图与验收项对应
- [ ] 未覆盖项写「待补证据」，不写「通过」
