# game-docs 标准与偏好

> 这是个人 / 团队偏好文件。其他团队可以整体替换本文件，不需要改 `SKILL.md` 的通用流程。

## 文档语言

- 设计文档、评审、ADR：中文
- 灰盒游戏 UI：英文占位（避免 Godot 默认字体缺中文字形）
- 代码注释：中文
- 正式版本地化：另开里程碑，不混进当前灰盒

## 6 人面板

固定角色：

1. 目标玩家
2. 游戏设计师
3. 技术负责人
4. 美术 / UX
5. 制作人
6. QA

每个角色必须给出：认可 / 条件 / 否决理由。结论只能是：通过 / 有条件通过 / 否决。

## 优先级

- **P0**：核心循环、阻断性错误、数据损坏、无法重开
- **P1**：体验、可读性、边缘优化、非阻断表现问题

P0 未全过，不进入下一里程碑。

> 跨 skill 约定：P0/P1 只用于**验收优先级**。功能/包优先级用 `High / Medium / Low`，避免同名不同义。

## 状态标记

与 `implementation-track` 共用：

- `◻` 未开始
- `🔄` 进行中
- `✅` 通过
- `❌` 失败（附原因）

## 文档编号

- 00 文档体系
- 01 单局简报
- 02 设计规范
- 03 验收矩阵
- 04 ADR
- 05 评审记录
- 06 试玩记录
- 07 检查清单

编号只追加，不复用。

## 默认里程碑

- **M0 立项**：01 / 02 / 03 / ADR / 评审
- **M1 灰盒**：可玩循环 + P0 验收 + 5 人试玩
- **M2 试玩**：内容、垂直切片、外部试玩

## 脚本环境

- 默认：Windows PowerShell 5.1+
- 非 Windows：手动复制 `references/templates/`，跳过 `scripts/`；或使用 PowerShell 7
- 路径示例统一用 `<target>`，不要在仓库里写死本机绝对路径

## 验收约定

- 固定种子必须可复现
- 每局日志包含：种子、结果、时长、统计、选择记录
- 性能测试必须记录机型 / CPU / GPU
- 验收用例不写「手感好」「看起来正常」

## 相关 skill

- `docs-audit`：文档集审核，可在评审前跑
- `roadmap-planning`：里程碑后的分期规划
- `implementation-track`：实现阶段的验收跟踪
- `code-digest` / `topic-research`：文档的外部输入
