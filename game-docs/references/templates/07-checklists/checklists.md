## M0 规范完成定义（DoD）

> 里程碑：立项 / 规范。目标：写代码前确认「这一局是什么」和「怎么验收」。

必须完成：

- [ ] `01-run-brief.md` 填完：一句话、单局参数、核心循环、灰盒范围
- [ ] `02-design-spec.md` 覆盖当前里程碑：状态、输入、核心系统、UI、性能、边缘情况
- [ ] 每条 P0 行为都有规则 ID
- [ ] `03-acceptance.md` 每条 P0 规则都有对应用例
- [ ] 关键方向 / 架构决策有 ADR，状态为 `Accepted`
- [ ] 6 人评审完成：签字表、行动项、结论齐全
- [ ] 评审行动项全部关闭
- [ ] 本地链接检查通过
- [ ] 没有残留占位符或「待填」标记
- [ ] 范围明确：Non-goals 写清楚

可以不做：完整数值平衡；全部内容清单；最终美术 / 音频；技术方案的全部细节。

退出条件：以上全部通过，且评审结论为「通过」或「有条件通过且条件已关闭」。

不通过：缺玩法定义 → 回 01；缺行为规则 → 回 02；缺验收 → 回 03；方向不成立 → 写新 ADR，不硬推。

## M1 灰盒完成定义（DoD）

> 里程碑：灰盒。目标：证明核心循环是否成立，不追求内容量。

必须完成：

- [ ] 一局能从头玩到尾：开始 → 核心交互 → 失败/胜利 → 重开
- [ ] 单局时长符合 01 的设定（允许 ±20%）
- [ ] `03-acceptance.md` 所有 P0 用例通过
- [ ] 5 名外部试玩完成，记录在 `05-reviews/`（或可选 `06-playtests/`）
- [ ] 试玩者中 ≥ 3 人愿意主动再开一局
- [ ] 无阻断性 bug
- [ ] 性能基线记录：机型、FPS、同屏上限、卡顿
- [ ] 固定种子可复现
- [ ] 日志包含种子、结果、统计、选择记录
- [ ] `02-design-spec.md` 已根据实现更新
- [ ] `03-acceptance.md` 已更新执行记录
- [ ] M1 6 人评审完成，行动项关闭

可以不完成：P1 用例；最终美术 / 音效；8 分钟 / Boss / 多角色；Meta / 存档 / 商店。

退出条件：P0 全过 + 试玩达标 + 评审通过 → 进入 M2。否则先改循环，不要加内容。

止损问题：5 人中 < 3 人想再来；说不出两局差异；不需要操作也能赢；选择只是数值 +10%；3 分钟内没有紧张时刻。

## 5 人试玩脚本

> 目标：验证「是否易懂、是否想再来、是否有变化」，不是收集「好不好玩」。每人 15~20 分钟。

准备：构建可运行、无阻断 bug；固定种子或不固定但记录清楚；录屏 / 记录表；不提前讲解；只准备 3 个问题。

开场（30 秒）只说三句：这是 3 分钟试玩；我不会教你，遇到问题直接说；死了也没关系，随时可重开。不要说「这个游戏是……」「你应该先……」。

观察前 3 分钟（不打断），记录：第一次按键用了多久；是否知道自己在做什么；第一次死亡是否明白原因；第一次升级是否比较选项；是否主动重开。

只问 3 个问题：刚才 30 秒内知道要做什么吗；死了想不想再来一局、为什么；这一局和上一局哪里不一样。

追问原则：问行为不问喜好；问「刚才为什么…」不问「你觉得…」；不辩护、不解释设计。
