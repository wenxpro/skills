# Workflow 03 — 验收矩阵

## 何时使用

- 02 已有行为规则，需要定义「怎么算完成」
- 灰盒完成，需要跑 P0/P1
- 要新增 / 修改验收用例

## 读取

- `references/templates/03-acceptance.md`
- 目标项目的 `02-design-spec.md`

## 步骤

1. **建立映射**
   - 逐条扫 02 的 P0 规则。
   - 每条至少一个 `AC-<类别>-<序号>`。
   - 缺失的标成 gap，不要假装覆盖。

2. **写用例**
   - 前置：状态、种子、数量、场景。
   - 操作：测试者做什么。
   - 预期：可观察、可判定。
   - 一条只验证一件事。

3. **标优先级**
   - P0：核心循环、阻断性错误、数据损坏。
   - P1：体验、可读性、边缘优化。

4. **写回归检查表**
   - 每次构建必跑的 8~12 条。
   - 不写「全部测试」，写最小闭环。

5. **补性能 / 日志**
   - 记录机型、FPS、同屏上限、卡顿。
   - 固定种子、日志字段、复现方式。

6. **执行记录**
   - 跑完后在「执行记录」写日期、版本、范围、结果。
   - 失败项链接到 Spec 规则 ID。

7. **自检**

   ```powershell
   .\scripts\check-docs.ps1 -DocsPath "<target>\docs"
   ```

## 完成标准

- 所有 P0 规则有对应用例
- 用例可判定，不含主观词
- 有回归检查表
- 有执行记录模板
- 检查通过

## 不要把

- 把「看起来正常」当预期
- 一条用例验证多个系统
- 只写 P0 不写 P1（或反过来）
- 用实现细节代替玩家可观察结果
