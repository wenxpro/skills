# Workflow 05 — 试玩

## 何时使用

- 灰盒第一次能完整跑一局
- 加入会改变体验的内容后
- 里程碑评审前

## 读取

- `references/templates/07-checklists/playtest-script.md`
- `references/templates/06-playtests/0000-playtest-template.md`

## 步骤

1. **准备**
   - 能运行的构建，无阻断 bug。
   - 记录版本 / 种子 / 场景。
   - 至少 5 名试玩者。
   - 不提前讲解玩法。

2. **观察前 3 分钟**
   - 多久知道操作？
   - 第一次死亡是否明白原因？
   - 第一次选择是否比较？
   - 是否主动重开？

3. **只问 3 个问题**
   1. 30 秒内知道要做什么吗？
   2. 死了想不想再来一局？为什么？
   3. 这局和上局哪里不一样？

4. **记录**
   - 用 `06-playtests/0001-日期-场景.md`。
   - 原话优先，不写「体验良好」。
   - 记录观察，不辩护设计。

5. **提炼**
   - 3 条观察
   - 3 条问题
   - 3 条行动，对应 Spec / 验收 ID

6. **更新文档**
   - 行为变化 → 改 02 + 03 + 变更记录。
   - 只改一个变量，再测。

7. **判断止损**
   - 5 人中 < 3 人想再来？
   - 玩家说不出两局差异？
   - 不需要操作也能赢？
   - 所有选择只是数值？
   - 触发任意一条：先改循环，不加内容。

## 完成标准

- 5 人记录完整
- 3 条观察 / 问题 / 行动
- 文档已同步
- 是否触发止损有明确结论

## 不要把

- 把「你觉得好玩吗」当核心问题
- 试玩中教玩家
- 试玩后同时改 5 个变量
- 用试玩数据替代验收矩阵
