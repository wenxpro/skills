# Workflow 02 — 写 / 更新 Design Spec

## 何时使用

- 01 已确认，需要把「这一局」写成行为规则
- 现有 Spec 与实现不一致
- 要新增系统，但必须先定义行为

## 读取

- `references/templates/02-design-spec.md`
- 目标项目的 `01-run-brief.md`
- 目标项目的 `00-README.md`（编号、状态、变更流程）

## 步骤

1. **锁范围**
   - 本里程碑做什么、不做什么。
   - 只写当前里程碑；未来内容放「开放问题」。

2. **写支柱**
   - 3~4 条，每条都要能用来否决需求。
   - 不写「好玩」「爽」这种不可验收的词。

3. **写状态机**
   - 状态表、转换表、暂停规则。
   - 明确：哪个状态暂停游戏时间、哪个 UI 仍可交互。

4. **写输入**
   - 哪个状态接受哪些输入。
   - 斜向归一化、UI 拦截、失焦处理。

5. **写核心系统**
   - 每个系统：属性 → 行为 → 结算 → 反馈 → 边缘情况。
   - 每条规则给 ID（`PLR-`、`SYS-`、`ENM-`、`SPWN-`、`XP-`、`UPG-`、`UI-`、`PERF-`、`EDGE-`）。
   - 公式写清楚，数值标「首版假设」。

6. **同步验收**
   - 每条 P0 规则在 `03-acceptance.md` 里有对应用例。
   - 没有用例的 P0 规则 = 没写完。

7. **写变更记录**
   - Spec 文末更新版本 / 日期 / 变更。

8. **自检**

   ```powershell
   .\scripts\check-docs.ps1 -DocsPath "<target>\docs"
   ```

## 完成标准

- 每条规则可判定
- 每个 P0 规则有验收
- 边缘情况已定义
- 没有未来里程碑内容
- 检查通过

## 不要把

- 把实现细节写进 Spec（对象池、节点路径）
- 把未验证的数值写成结论
- 把「手感好」当规则
- 一次写完所有系统却不跑灰盒
