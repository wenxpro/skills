# Workflow 06 — 变更与维护

## 何时使用

- 要改已有行为、数值、状态、UI
- Spec 与实现不一致
- 需要新增系统，但不想让文档漂移

## 步骤

1. **定位影响面**
   - 找到受影响的规则 ID（`STATE-`、`SYS-`、`XP-` 等）。
   - 找到对应的验收 ID（`AC-...`）。

2. **先改 Spec**
   - 更新规则、公式、边缘情况。
   - 在文末写变更记录。

3. **再改验收**
   - 增加 / 修改验收用例。
   - 如果行为变了但验收没变，说明还没改完。

4. **判断是否要 ADR**
   - 方向、架构、存档、联机、付费、平台 → 写新 ADR。
   - 纯数值 / UI 文案 → 不需要。

5. **自检**

   ```powershell
   .\scripts\check-docs.ps1 -DocsPath "<target>\docs"
   ```

6. **验证**
   - 跑受影响的 P0 用例。
   - 记录执行结果。

## 完成标准

- Spec / Acceptance / 变更记录三者一致
- 受影响的 P0 用例已跑
- 需要时已有新 ADR
- 检查通过

## 不要把

- 只改代码不改文档
- 只改 Spec 不改验收
- 用「小改动」跳过变更记录
- 在评审里口头承诺，不写行动项
