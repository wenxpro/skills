# Godot 游戏运行时

目标：把 Godot 引擎特有的工程问题收在一层，避免动画、战斗、UI、音频各自重复造运行时。

本 skill 只负责**引擎适配与工程集成**；3D 资产/动画规则用 `game-animation-rig`，打击反馈用 `game-feel`，战斗模型用 `game-combat-model`，UI 视觉规范用 `ui-baseline`。

## 何时使用

- 新建或重整 Godot 项目入口、场景树、InputMap、测试场景
- 接入 AnimationTree、AudioServer、`user://` 设置、headless 回归
- 需要脚本化截图、分辨率矩阵、CLI 测试模式
- 排查「编辑器里能跑、headless 不行」「设置不持久」「音频总线没有声音」「导入后脚本/资源丢失」

不适用：

- 3D 资产坐标、重定向、脚底接触、动画状态机设计 → `game-animation-rig`
- hitstop、震屏、闪白、trail、音效分层 → `game-feel`
- 战斗数值、攻击时间轴、克制预算 → `game-combat-model`
- UI token、组件状态、无障碍 → `ui-baseline`
- 项目文档槽位与验收 → `game-docs`

## 行为

参考型 skill，无主动打断。用户要求搭 Godot 运行时、headless 回归、设置持久化或排查引擎集成问题时使用。

## 核心规则

### 1. 单一工程入口

- `project.godot` 是唯一工程配置源；主场景、窗口、渲染、音频总线只在这里定义。
- 测试场景是主场景的薄壳，不复制一份配置。
- 运行时参数用命令行显式传入；不要靠改项目文件切换测试模式。

### 2. 输入映射只有一处

- InputMap 要么在项目设置，要么在运行时统一注册；不要两处各写一半。
- 键鼠与手柄都映射到语义动作；UI 导航、确认、返回单独检查。
- 死区、轴向、组合键写进输入注册处，不散落在业务脚本。

### 3. 场景树职责

- 根脚本只做编排：创建角色、相机、HUD、音频、测试模式。
- 战斗结算、表现、HUD 更新分开；HUD 不参与规则。
- 测试模式用显式分支或独立场景；不要把测试代码塞进正常输入路径。

### 4. headless 与回归

- headless 下不创建音频/渲染依赖；需要时显式跳过，而不是等引擎报错。
- 测试必须可失败：失败用非零退出码，成功打印稳定标记。
- 固定帧/固定步长优先于墙钟时间；断言输出而不是截图。
- Windows 用 PowerShell 运行器时，捕获 stdout/stderr 和退出码；不要只读控制台最后一行。

### 5. AnimationTree 接口

- 状态名、参数路径、clip 名保持稳定；外部只通过方法设置，不直接改内部节点。状态内容与资产规则由 `game-animation-rig` 定义；本 skill 只保证接口稳定。
- 时间缩放、循环、BlendTree 输出连接由适配层统一处理。
- 同一 clip 的 loop mode 与状态 loop mode 都要设置；只设一处会停在末帧。
- 动画状态与玩法状态分离：玩法状态决定「该播什么」，动画层决定「怎么播」。

### 6. 音频总线

- 先定义总线拓扑（Master / 分组 / 音乐），再创建播放器。
- 所有播放器显式指定总线；不要依赖默认 Master。
- 音量、静音、默认值集中管理；改设置立即写 AudioServer。
- 持久化只存用户偏好，不存运行时音量快照。
- headless 下不创建播放器，避免测试泄漏。

### 7. 持久化

- 用户设置放 `user://`，不写项目目录。
- 读取时先填默认值，再覆盖；缺文件/缺键不能崩。
- 保存失败要可见；不要静默吞掉。
- 测试用独立配置路径，不读真实用户配置。

### 8. 导入与生成文件

- `.uid`、`.import`、缓存目录按引擎规则处理；不手改生成内容。
- 资源缺失时显式报错或 fallback；不要静默变 T-pose/静音/空场景。
- 二进制资产是否入库由许可证与仓库策略决定；本地实验资产用忽略规则隔离。
- 不把本机绝对路径写进场景或脚本。

### 9. 截图与窗口

- 截图用窗口模式，不用 headless；先设置目标分辨率，再等渲染帧。
- 截图前把角色/战斗状态固定，避免随机帧；分辨率与 UI 布局一起验。
- 截图是证据，不是规则；规则仍由断言和验收用例证明。
- 需要两种分辨率时，分别启动并记录实际输出尺寸。

### 10. 失败要显式

- 缺场景、缺节点、缺总线、缺 clip、缺输入动作时，给可定位的错误。
- fallback 必须写进文档；不能把 fallback 当成正常路径。
- 运行器失败时保留输出文件；不要覆盖上一次证据。

## 检查清单

- [ ] `project.godot` 是唯一工程配置源，测试场景不复制配置
- [ ] InputMap 只有一处注册，键鼠/手柄/UI 导航都覆盖
- [ ] 根脚本只编排，战斗/表现/HUD 职责分离
- [ ] headless 不依赖音频/渲染，失败有非零退出码和稳定标记
- [ ] 测试用固定帧/固定步长，不靠墙钟
- [ ] AnimationTree 状态名、参数路径、clip 名稳定
- [ ] 音频播放器全部显式总线，音量/静音实时生效
- [ ] 设置只写 `user://`，读取有默认值，保存失败可见
- [ ] `.uid`/`.import` 不被手改，资源缺失有显式错误
- [ ] 截图固定状态、固定分辨率、窗口模式，记录实际尺寸
- [ ] 不把本机路径、项目专有命令写进通用规则

## 输出

- 运行时检查表：`references/runtime-checklist.md`
- 排查记录：按「现象 / 判断 / 修复 / 证据」输出
- 引擎适配建议：只写通用模式；项目命令、场景名、数值放项目文档

## 反模式

- 把测试开关写进正常输入路径
- headless 下仍创建音频/截图依赖
- 用墙钟时间做确定性测试
- InputMap 一半在项目设置、一半在运行时
- 播放器不指定总线，靠默认 Master
- 设置写在项目目录或读取真实用户配置做测试
- 手改 `.uid`/`.import` 或提交本机缓存
- 用截图代替断言，或用断言代替真人试玩

## 交接

- 3D 资产/重定向/脚底/AnimationTree 细节 → `game-animation-rig`
- 打击反馈/hitstop/震屏/trail → `game-feel`
- UI token/组件/无障碍 → `ui-baseline`
- 验证计划/证据层级 → `validation-design`
- 项目文档/验收矩阵 → `game-docs`
- 实现执行与提交 → `delivery-stage` / `git-commit`

## 边界

- 不写具体项目命令、场景名、数值、路径
- 不替代动画管线、战斗模型、UI 规范
- 不把引擎版本差异写成绝对规则；版本差异放项目适配说明
- 只解决 Godot 运行时与工程集成，不评价游戏内容
