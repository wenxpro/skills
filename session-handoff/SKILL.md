# 会话边界与外部记忆

目标：把「当前任务的工作记忆」外置成一页可验证的 handoff，让新会话不必重述历史，也不会把旧推理当事实。

## 何时使用

- 一个工作包/阶段结束，准备进入下一个
- 会话明显变长、响应变慢、反复总结
- 需要并行会话、切换模型/工具/权限
- 需要暂停任务，之后再继续
- 新会话要接手当前任务
- 不确定「继续」还是「新开窗口」

## 回复前边界自检

准备最终回复前，如果本回合满足任一条件，先做一次边界自检：

- 刚完成/关闭一个工作包
- 刚提交、合并或验收收口
- 上下文出现压缩、反复总结、响应变慢
- 下一步将进入不同工作包
- 用户问「接下来做什么」

自检 3 问：

1. 是否还有未提交、未记录的状态？
2. 下一步是否不同工作包？
3. 新会话能否只读 handoff + 仓库，复述下一步第一条命令和验证方式？

任一为是 → 写 handoff，并主动建议新开窗口；都为否 → 不提示。
同一工作包只提示一次；不要每次回复都问。

不适用：

- 单点问答、代码解释、一次性小修
- 同一任务内的高频调试循环
- 纯设计讨论，还没有可落盘的状态
- 替代文档、ADR、验收或检索本身

## 记忆分层

| 层 | 载体 | 内容 | 生命周期 |
|---|---|---|---|
| 长期记忆 | 仓库文档、ADR、验收、测试、提交 | 决策、规则、边界、证据 | 版本化，跨会话 |
| 工作记忆 | handoff | 当前目标、状态、下一步、约束、未决项 | 当前任务；完成后归档/丢弃 |
| 临时记忆 | 聊天、工具日志、推理草稿 | 探索过程、失败尝试、原始输出 | 会话内，默认不落盘 |

规则：长期记忆 + 工作记忆可以跨会话；临时记忆不是事实源。

## 核心规则

1. **状态先落盘，会话后切换。** 未提交改动、未记录决策、未写下一步，不切换。
2. **在边界切换。** 工作包/阶段边界适合新会话；调试中途切换要先写 checkpoint。
3. **一页 handoff。** 只写会影响下一步的内容；链接文件/提交，不粘贴全文。
4. **新会话先复述再验证。** 复述目标、当前状态、下一步第一条命令；复述不对，handoff 不完整。
5. **存决策与证据，不存思考过程。** 推理草稿、工具流水、原始日志默认不落盘。
6. **不利用新会话逃避未决决策。** 未决问题先记录 owner 与下一步，再切换。
7. **写任务先隔离。** 只读讨论可以共享主工作区；写代码/文档/配置/资源默认用 `worktree-workflow` 建独立 worktree，一个 worktree 一个写者。
8. **长期记忆保持单一事实源。** handoff 只引用 docs/ADR/验收，不复制规则。

## 继续还是新开

| 继续当前会话 | 新开会话 |
|---|---|
| 同一工作包、同一批文件 | 工作包/阶段切换 |
| 紧测试-修复循环 | 上下文变慢、反复总结、旧约束开始丢失 |
| 决策还在讨论、尚未稳定 | 需要干净实现上下文 |
| 切换成本明显高于收益 | 并行任务、模型/工具/权限切换 |
| handoff 还写不出来 | handoff 已能复述并验证 |

判断句：

> 新会话能否只读 handoff + 仓库，在几分钟内说出「下一步第一条命令」和「怎么验证」？能，就切换；不能，就继续或补 handoff。

## 何时主动提示用户

只在边界明确、且 handoff 能写出来时提示；先按「回复前边界自检」判断；不要每轮追问。

| 强度 | 条件 | 动作 |
|---|---|---|
| 必须提示 | 工作包/阶段完成，下一步是不同工作包 | 建议先写 handoff，再新开 |
| 必须提示 | 本回合刚提交/合并/验收收口，且下一步是新工作包 | 先做回复前自检，再建议 handoff/新开 |
| 必须提示 | 需要切换模型、工具、权限或工作区 | 先写 handoff，再切换 |
| 必须提示 | 要改代码/文档/配置/资源，或需要并行修改同一仓库 | 用 `worktree-workflow` 建独立 worktree；只读讨论可留主工作区 |
| 建议提示 | 上下文变慢、反复总结、开始丢失早期约束 | 先写 handoff，再判断是否切换 |
| 建议提示 | 同一问题多次修复仍无新证据 | 记录失败命令/日志/假设，再建议新会话 |
| 不提示 | 同一工作包内的测试-修复循环 | 继续当前会话 |
| 不提示 | 未提交、未记录决策、handoff 写不出来 | 先收尾，不切换 |
| 不提示 | 单点问答、小修、用户明确说继续 | 继续当前会话 |

提示话术：

```text
当前工作包已完成，下一步 <X> 是独立工作包。
建议先写一页 handoff，再新开窗口做 <X>。要我现在写吗？
```

规则：

- 每个工作包最多提示一次；用户拒绝后继续，不重复追问。
- 提示前先检查：目标、当前状态、下一步第一条命令、验证方式能否写出来；写不出来就不提示。
- 不把“新开会话”说成必须；给理由和 handoff 选项，由用户决定。

## Handoff 最小内容

1. 目标 / DoD
2. 当前状态：已完成 / 进行中 / 阻塞
3. 关键决策 + 文档链接
4. 文件、提交、测试结果
5. 下一步：第一条命令
6. 约束 / 不要动的东西
7. 未决问题 + owner
8. 验证方式
9. 建议加载的 skill

模板见 `templates/session-handoff.md`。

## 触发门

出现以下任一情况，先写 handoff，再决定是否新开：

| 触发 | 先做什么 |
|---|---|
| 工作包完成 | 提交/保存 + 更新验收 + 写 handoff |
| 上下文变慢/反复总结 | 写当前状态、下一步、验证；再新开 |
| 模型/工具/权限切换 | 写 handoff + 记录环境差异 |
| 写任务/并行写 | 用 `worktree-workflow` 隔离；一个 worktree 一个写者 |
| 任务阻塞 | 写清阻塞点、已尝试、可选方案 |

## 输出要求

一次会话边界处理，至少留下：

1. 继续还是新开的结论
2. handoff 文件/位置
3. 当前状态与下一步第一条命令
4. 验证方式
5. 未决问题与 owner
6. 需要同步的长期记忆（docs/ADR/验收/提交）；跨项目时附接口版本与双方仓库 HEAD

## 边界与反模式

- 不替代 `execution-loop`：一个负责会话内连续执行，一个负责会话边界与交接。
- 不替代文档/ADR/验收：那些是长期记忆，handoff 只是工作记忆。
- 不把聊天记录、推理草稿、原始日志当 handoff。
- 不为每个小任务新开会话；边界不清时先继续。
- 不在未提交、未记录的状态下切换。
- 不让两个会话同时写同一 worktree；写任务用 `worktree-workflow`。
- 不把过期 handoff 当当前事实；完成后归档或标 `Superseded`。

| Skill | 关系 |
|---|---|
| `docs-core` | 长期记忆的文档槽位与单一事实源 |
| `game-docs` | 游戏项目文档与验收 |
| `execution-loop` | 当前会话内连续执行到目标 |
| `worktree-workflow` | 读写分流与写任务的工作区/分支隔离 |

| `implementation-track` | 验收状态与偏差是 handoff 的事实源 |
| `cross-project-integration` | 跨项目交接模板、接口版本、双方仓库 HEAD |
| `git-commit` | 切换前提交/保存 |
| `review` | 需要决策评审时使用 |
| `docs-audit` | 检查长期记忆是否过期/漂移 |
