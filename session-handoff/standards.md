# 会话边界与外部记忆规范

> 这是个人/团队偏好文件。其他团队可以整体替换，不需要改 `SKILL.md`。

## 默认边界

- 一个工作包一个会话；同一工作包内优先继续。
- 阶段切换（设计 → 交付 → 反馈）默认是新会话边界。
- 纯讨论、方案未定、关键决策未落盘时，不切换。
- 切换前至少完成一件事：提交、保存、或写出可验证的 handoff。

## 上下文信号

出现以下信号时，考虑收尾当前会话：

- 响应明显变慢，或反复要求总结
- 工具输出占据大部分上下文
- 开始忘记/混淆早期约束
- 同时推进多个独立任务
- 需要换模型、工具、权限或工作区
- 当前任务已经能写成「下一步 + 验证」

不要用固定 token 数当唯一阈值；看任务边界和可验证性。

## 提示阈值（示例，可按团队调整）

- 同一工作包内：不主动提示新开。
- 工作包/阶段完成：提示一次，附 handoff 选项。
- 连续两次需要重新总结或重新读同一批文件：建议提示。
- 同一问题连续三次修复仍无新证据：建议提示；先记录失败证据。
- 用户明确说“继续/先别换”：不提示，直到下一次工作包边界。
- 每个工作包最多提示一次；不重复追问。

提示话术：

```text
当前工作包已完成，下一步 <X> 是独立工作包。
建议先写一页 handoff，再新开窗口做 <X>。要我现在写吗？
```

## 会话类型

| 类型 | 适合 | 不适合 |
|---|---|---|
| 设计 | 目标、边界、方案、评审 | 连续实现、大规模回归 |
| 交付 | 实现、测试、审查、提交 | 未确认的范围变化 |
| 反馈 | 结果分类、验收更新、回流 | 当前实现、代码审查本身 |
| 审查 | 代码/方案/文档评审 | 代替实现或状态跟踪 |

可以合并小任务；跨类型且状态复杂时分开。

## Handoff 质量

一份合格 handoff：

- 一页内；能独立阅读
- 目标/DoD 清楚
- 已完成 / 进行中 / 阻塞分开
- 决策有链接，不复制长文
- 下一步是**第一条命令**，不是“继续优化”
- 约束/不要动的东西明确
- 未决问题有 owner
- 验证方式可执行
- 包含日期、提交号、测试结果

## 记忆卫生

- 长期记忆：docs/ADR/验收/测试/提交；版本化，不随手改历史。
- 工作记忆：handoff；任务完成后归档或删除，不长期占用入口。
- 临时记忆：聊天/推理/日志；默认不落盘。
- 过期 handoff 标 `Superseded`，不能继续当当前事实。
- 不重复维护同一事实；handoff 只引用长期记忆。

## 读写分流与并行会话

- 只读讨论/调研可以共享主工作区；写任务默认独立 worktree/分支。
- 一个 worktree 同一时间只保留一个写者。
- 其他会话可以只读探索、调研、审查。
- 需要并行实现时，用独立 worktree/分支，并在 handoff 写清路径与范围。
- 合并前重新读长期记忆和验收，避免两个会话各自“记得”不同版本。

## 模型/工具切换

- 切换前写 handoff，记录模型/工具差异和未验证项。
- 新模型先复述目标与下一步，再跑最小验证。
- 不默认“新模型记得旧上下文”；以仓库和 handoff 为准。

## 反模式

- 用新会话逃避一个难 bug，却没有失败命令/日志/假设。
- 把整段聊天或推理草稿贴进 handoff。
- handoff 写“继续做”，没有第一条命令。
- 未提交就切换，旧会话一关状态丢失。
- 两个会话同时改同一批文件。
- 过期 handoff 不归档，后续会话继续引用。
