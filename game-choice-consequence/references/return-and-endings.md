# 回访与结局

## 1. 回访

| 字段 | 要定义 |
|---|---|
| 谁回来 | 角色/组织/事件 |
| 触发 | 时间/状态/选择 |
| 次数 | 一次/多次/可错过 |
| 变化 | 称呼/态度/价格/物品/环境 |
| 错过 | 是否永久错过、是否有替代 |
| 可识别 | 玩家如何认出「这是我之前的选择」 |

检查：

- 回访不是随机事件，能追溯到选择
- 错过有提示/可接受，不是无预警惩罚
- 回访不依赖开发者记忆；状态表能查
- 回访次数有限，避免内容爆炸

## 2. 结局

| 字段 | 要定义 |
|---|---|
| 条件 | 必须/禁止/权重 |
| 优先级 | 互斥/覆盖顺序 |
| 兜底 | 没有满足时用哪个 |
| 回应 | 回应哪些主要选择 |
| 可达 | 自动遍历/脚本验证 |

检查：

- 没有不可达结局
- 没有永远被高优先级覆盖的结局
- 结局回应主要选择，不只最后一个选项
- 结局数量服务表达，不追求数量

## 3. 验证

- 选择矩阵：每个选项写入/读取
- 回访矩阵：触发/次数/错过
- 结局覆盖：自动遍历所有结局
- 试玩：理解、后悔、想重玩
- 反例：玩家觉得「选什么都没差」→ 后果层失败
