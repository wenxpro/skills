# 验收类别与证据

本文件定义验收项的分类、证据阶梯与判定规则。槽位与状态语义见 `SKILL.md`；项目文档用自己的验收模板时，类别与规则仍适用。

## 1. 类别

| 前缀 | 类别 | 回答 | 示例 |
|---|---|---|---|
| `AC-FUNC` | 功能 | 行为是否符合规则 | 导入 50 个条目成功 |
| `AC-UI` | UI/视觉 | 布局、组件、状态是否一致 | 浅色/深色、空/错误状态 |
| `AC-A11Y` | 无障碍 | 残障用户能否完成主路径 | 屏幕阅读器、动态字号、对比度 |
| `AC-SEC` | 安全 | 资产与边界是否受保护 | 越权、注入、密钥、重放 |
| `AC-PERF` | 性能 | 延迟、吞吐、资源是否达标 | 冷启动、接口延迟、内存 |
| `AC-REL` | 可靠性 | 失败、恢复、容量是否可控 | 超时、重试、备份恢复 |
| `AC-DATA` | 数据 | schema、一致性、迁移、保留是否正确 | 迁移演练、回填校验 |
| `AC-COMPAT` | 兼容 | 版本、平台、客户端是否兼容 | 旧客户端、旧数据、浏览器 |
| `AC-COMPLIANCE` | 合规 | 法规、隐私、审计是否满足 | 数据删除、同意、留存 |
| `AC-OPS` | 运维 | 发布、回滚、告警、运行手册是否可用 | 回滚演练、告警演练 |

规则：

- 一个验收项只属于一个主类别；跨类别拆开。
- P0/P1 只表示验收优先级，不表示功能优先级。
- 非功能类别不能因为「难测」省略；无法测就写「待补证据」。

## 2. 证据阶梯

从弱到强：

1. 静态检查 / 人工核对
2. 单元测试
3. 集成测试 / 接口测试
4. 端到端测试 / 真机 / 浏览器
5. 线上观察 / 演练 / 监控

规则：

- 证据级别要与风险匹配；安全、数据迁移、回滚至少到第 3 级或演练。
- 一条验收项至少一份证据；证据放项目 `evidence/`，文档只链接。
- 证据必须可复现：命令、样本、环境、日期、结果。
- 截图/日志/报告都算证据，但不能替代可重复的测试。

## 3. 判定

| 情况 | 结论 |
|---|---|
| 有匹配证据且通过 | ✅ 通过 |
| 部分通过，剩余有 Owner/截止 | 🔄 进行中 |
| 无法执行或环境缺失 | ◻ 未开始；标「待补证据」 |
| 执行失败 | ❌ 失败 |
| 明确不适用 | `N/A` + 原因 + 批准人；不算通过 |
| 跳过 | `SKIP`；不算通过 |

- `SKIP` 不等于通过；`N/A` 不等于通过。
- 不允许为了通过而放宽阈值；阈值变化按「阈值与基准值变更」记录旧值、新值、原因、样本、日期。
- 非功能项没有证据时，评审结论只能是「有条件通过」或「待补证据」。

## 4. 与评审的关系

- `review` 的软件/架构 profile 用本表检查证据是否齐全。
- 高风险项按 `backend-design` 的风险角色追加安全/数据/SRE/API owner。
- UI 项按 `ui-baseline/references/review-checklist.md` 检查截图与状态。
- `implementation-track` 只更新状态与偏差，不重写验收项。
