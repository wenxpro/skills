# 文档体系核心契约

目标：每类内容只有一个归属文档，每次变更只改该改的地方。本 skill 只定义契约，不提供模板；模板与领域规则由具体 skill（如 `game-docs`）提供。

> 槽位到编号/文件的映射在 `standards.md`，替换它即可适配不同领域。

## 文档槽位

任何项目的文档体系由 7 个槽位组成，数量可减、职责不可混：

| 槽位 | 回答的问题 | 内容 |
|---|---|---|
| 入口 | 从哪开始看？ | 索引、状态、导航、变更流程 |
| 假设 | 为什么做这个？验证什么？ | 一页纸目标、范围、止损条件 |
| 契约 | 具体行为是什么？ | 可判定的规则，每条有 ID |
| 验收 | 怎么判定做完了？ | 可执行用例，映射回契约 ID |
| 决策 | 为什么这么选？ | ADR：备选、对比、否决理由 |
| 证据 | 验证结果如何？ | 评审记录、试玩/测试结果 |
| 检查 | 什么时候算完成？ | DoD、自检清单 |

槽位可按项目裁剪（小项目可无 ADR 目录），但不能让同一事实出现在两个槽位。

## 单一事实源

- 行为在「契约」，验收在「验收」，证据在「证据」
- 其他文档只引用，不复制内容
- 规划只排期、跟踪只更新状态、评审只写结论——都不重写规则

## 行为变更三件套

任何行为变更，按顺序：

1. 改「契约」，更新规则 ID
2. 改「验收」，增加/修改对应用例
3. 写变更记录

方向/架构级变更追加：新 ADR + 评审。

不允许：只改代码不改契约、只改契约不改验收、口头承诺不落记录。

## 状态语义

- 文档状态：`Draft / Proposed / Accepted / Conditional / Superseded`
- 验收状态：`◻ 未开始 / 🔄 进行中 / ✅ 通过 / ❌ 失败`
- 评审结论：`通过 / 有条件通过 / 否决`（归档：`Superseded / Archived`）
- 优先级：P0/P1 只用于验收；功能/包优先级用 `High / Medium / Low`
