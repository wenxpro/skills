# 重构操作手册

## 拆分组合根（Split Composition Root）

适用：组合根（Composition Root，应用启动时唯一的依赖装配入口）同时承担装配与业务逻辑，退化为 god object。

手法：Extract Function / Extract Class（提炼）→ Move Function（搬移）→ 旧入口保留 Delegation（行为保持）。

分两阶段，先低风险后高风险：

| 阶段 | 抽什么 | 不做什么 |
|---|---|---|
| A 低风险 | 参数解析、日志/结算、ViewModel/展示数据、背景绘制、纯格式化 | 不改状态机、不改领域规则 |
| B 收口 | 请求/流程编排、事件路由、状态/变换协调、副作用或结算发放 | 不同时加新内容，不引入全局事件总线 |

规则：

1. **行为保持**：每拆一个模块跑全量测试 + golden 回归 + 性能基线；指标漂移就停。
2. **保留旧入口包装**：启动、重置、事件处理等旧入口先转发到新模块，避免一次性改测试。
3. **每个切口单独提交**：一个模块一个可回滚提交。
4. **组合根只做装配、信号连接、输入转发**；行数只是症状，所有权才是目标。
5. **不为拆而拆**：按职责聚合，不按方法数量拆类。

反模式：先重写状态机、同时改内容和重构、引入全局事件总线、用「行数下降」代替边界验收。

## 行为保持重构安全门

1. 重构前记录基线：测试、固定种子/黄金输出、性能、关键业务指标。
2. 每个切口后重跑同一组基线；必须逐项一致，而不是「看起来差不多」。
3. 不一致时先回滚该切口，不要继续叠加。
4. 兼容包装保留到调用方全部迁移完；删除包装要有单独提交。
5. 如果重构需要改变行为，停止，走规则/验收/ADR 流程。
