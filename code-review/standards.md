# Code Review 标准与偏好

> 这是个人/团队偏好文件。其他团队可以整体替换，不需要改 `SKILL.md`。

## 审查规模

- 小 diff（单文件/单行为）：全量读，至少覆盖失败路径。
- 中等 diff：按风险排序，先读状态/数据流，再读 UI/表现。
- 大 diff：按工作包拆分审查；不把多个无关改动塞进一次结论。
- 单次审查超过约 400 行有效改动时，要求拆分或分两次审查（示例阈值，可按团队调整）。

## 阅读顺序

1. 入口和调用链：谁触发、什么时候触发、失败时走哪。
2. 状态归属：谁创建、谁修改、谁销毁；reset 后是否残留。
3. 边界和约束：0、上限、空集合、重复、并发/时序。
4. 失败路径：错误是否被吞、日志是否可定位、是否静默降级。
5. 资源生命周期：节点/句柄/计时器/缓存是否释放，重开是否翻倍。
6. 测试：断言是否对应规则，是否覆盖上面五项的失败路径。

## 按项目类型的检查清单

### 游戏

| 改动类型 | 必须跑的检查 | 备注 |
|---|---|---|
| 数值/平衡表 | 配置校验测试 + 多种子分布回归 | 字段存在、范围、跨字段约束；记录 P50/P90 |
| 状态重置/重开 | 同一实例重复运行的重开一致性测试 | 关键指标一致；不能只比较两个新进程 |
| UI/世界标记 | 数量上限、合并、刷新频率 + 性能测试 | 防止标记数量随实体数线性增长 |
| 内容表/关卡表 | 内容校验 + 文档检查 | ID 唯一、引用存在、旧数据作废 |
| 战斗/生成路径 | 真实模拟 + 固定种子回归 | bot/模型是观察工具，不替代真人 |

示例（仅示意，不是规则）：改拾取/合并参数时，同时验证「拾取半径 < 合并半径」这类跨字段约束；重开测试比较同一局实例连续三局的关键指标。

### 软件

| 改动类型 | 必须跑的检查 | 备注 |
|---|---|---|
| 配置/环境变量 | 配置校验测试 + 启动检查 | 缺省值、必填项、类型/范围 |
| 数据/迁移 | 迁移测试 + 回滚演练 | 幂等、顺序、旧数据兼容 |
| 接口/协议 | 接口测试 + 兼容性用例 | 版本、错误码、超时 |
| 并发/重试 | 竞态/幂等测试 | 重复请求、超时、部分失败 |
| 性能关键路径 | 基准测试 + P95/内存 | 样本量、预热、环境固定 |

### 服务

| 改动类型 | 必须跑的检查 | 备注 |
|---|---|---|
| 发布/部署 | 回滚方案 + 健康检查 | 灰度、超时、熔断 |
| 监控/告警 | 指标/日志/追踪检查 | 能定位到请求/用户/版本 |
| 权限/密钥 | 安全审查 + 最小权限检查 | 不把密钥写进日志/仓库 |
| 定时/队列 | 重复执行/积压测试 | 幂等、死信、重放 |

## 基准值与阈值重定

- 行为变化后，旧基准值默认失效；在验收/回归文档标「旧值作废」，不要继续引用。
- 用和旧基准值相同的样本设计重跑（种子/模型/时长/环境），再回填新值。
- 阈值变更必须写清：旧值、新值、原因、样本、日期、批准人。
- 不能为了让失败变绿而放宽阈值；先判断是实现错误、测试错误还是设计变化。
- 样本不足时输出显式 `SKIP` 并说明原因；`SKIP` 不计入通过率。
- 基准值记录至少包含：命令、提交、样本量、分位数、环境。

## 结论语义

- `通过`：必须修项为 0；检查全部执行且通过；剩余风险已记录。
- `有条件通过`：无必须修项，但有关键检查缺失/建议修项待补；条件必须可执行、有负责人和截止。
- `不通过`：存在必须修项，或关键检查未执行/失败。

## 反模式

- 只读 diff 不跑测试；只跑测试不读失败路径。
- 用「测试全绿」跳过审查，或用「审查通过」跳过测试。
- 发现必须修的问题后只改表面症状，不复跑根因。
- 把 flaky 测试重跑几次就当通过。
- 为了让检查通过而改阈值，且不记录原因。
- 审查记录只写「没问题」，没有范围、依据和剩余风险。
