# 实现跟踪规范（个人/团队风格标准）

本仓库（cheese/pi-agent 项目文档集）约定如下，其他团队可整体替换。

## 验收跟踪表位置

- 编号验收（M1-M20）状态汇总：PRD 第六节「MVP 实现状态（执行视图，随实现更新）」
- 包级验收状态：各包 DESIGN.md（就近工程，随包更新）
- 验收判定标准：对应论证文档末尾验证清单（如内核闭环验证清单①-⑥）

## 状态标记

◻ 未开始 / 🔄 进行中 / ✅ 通过 / ❌ 失败（附原因）

## 偏差记录格式

四段式：现象（可复现）→ 判断（违反哪条编号原则）→ 修复（实际改动）→ 回写（回写论证文档并带日期，或标注留待评审）

## 实现顺序参考（本项目已验证的依赖链）

agent-core（循环引擎）→ coding-agent（工具/装配/会话）→ ai（provider 防腐层）→ cli（全链路组装）→ tui（前端壳）。新功能先确认包边界再动手。

## 测试纪律

- 全库测试全绿才算验收通过
- 测试/验证读真实配置的坑（本机 ~/.cheese/config.json 是真实 key）：配置目录必须指向临时位置（如显式 --agent-dir），防止泄露
- 文件操作（write_file）失败必须确认重写，不假定成功
- 真实厂商验证用临时 env 注入 key，验证后删除，不落命令历史
