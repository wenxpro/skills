# 代码库梳理规范（个人/团队风格标准）

本文件存放 `code-digest` 中依赖具体项目习惯的部分。本仓库（cheese/pi-agent 项目文档集）的约定如下，其他团队可整体替换。

## 项目特有素材（cheese/pi-agent）

- 语义记录：偏差记录——解释「为什么这么改」的演进来源（git 只记「发生了什么」），建时间线时并入
- 决策编号体系：A1/A5 等，逐条核对代码落实情况
- 验收编号：M1-M20

## 证据标注格式

与 `topic-research` 一致：写进文档的结论带日期与实测方式后缀：

- 「（2026-08-10 源码结构实测）」「（2026-08-10 git 历史核对）」
- 推断必须显式写「推断」或「未验证」
- 代码出处标注文件路径 + 行号，如 `packages/agent-core/src/agent-loop.ts:42`

## 梳理入口（本项目约定：文档先行）

本项目每个包有就近 DESIGN.md，梳理顺序固定：

1. 包 DESIGN.md（职责、机制、验收状态）→ 验收跟踪表（M1-M20，见各包 DESIGN.md 与演进计划文档）→ 源码
2. 演进语义记录在演进计划文档与各包 DESIGN.md 的偏差节（如「偏差 N：现象 / 判断 / 修复」），git log 的语义补充
3. 决策编号体系：设计约束 A1/A4/A5/A7/C6/E3 与验收 M1-M20，核对代码落实情况时逐条对照

## 行为验证隔离纪律

- 本机 `~/.cheese/config.json` 是真实 key（0600），梳理/验证时配置目录必须指向临时目录（如 `--agent-dir` 指向 temp），禁止读真实配置
- 验证 key 不落命令历史、不入 git；用完删除
- 伪 TTY 验证用管道 + EOF（`printf "xxx\n/exit\n" | cheese --offline`），不用 script 命令包裹

## 文档落点约定

- 演进时间线 → 设计总纲演进史章节，不建独立文档
- 模块技术细节 → 就近各包 DESIGN.md
- 过时核对结果 → 原文修正，不另立文档
- 与结论无关 → 丢弃

## 技术细节粒度

值得写进文档的细节：机制与取舍、数据结构、边界情况、依赖与版本约束。不写：逐行注释式描述、显而易见的内容。

## 调研纪律（沿用 topic-research）

- 证据等级：S 级（源码逐行读）、A 级（官方文档/依赖清单/仓库结构）、B 级（行为观察）
- 无证据就是推断；推断必须标注
- 文档已写入的结论被代码推翻时，先改文档再说明
