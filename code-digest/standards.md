# 代码库梳理规范（个人/团队风格标准）

本文件存放 `code-digest` 中依赖具体项目习惯的部分。以下为默认偏好，其他团队可整体替换。

## 项目特有素材（示例）

- 语义记录：偏差记录——解释「为什么这么改」的演进来源（git 只记「发生了什么」），建时间线时并入
- 决策编号体系：如 `A1/A5` 等（项目自定义），逐条核对代码落实情况
- 验收编号：如 `AC-*` 或项目自定义编号

## 证据标注格式

与 `topic-research` 一致：写进文档的结论带日期与实测方式后缀：

- 「（2026-08-10 源码结构实测）」「（2026-08-10 git 历史核对）」
- 推断必须显式写「推断」或「未验证」
- 代码出处标注文件路径 + 行号，如 `packages/agent-core/src/agent-loop.ts:42`

## 梳理入口（文档先行）

按项目实际文档结构选入口，不假定一定有包级设计：

1. **有包级设计**（monorepo/多模块）：包级设计文档（职责、机制、验收状态）→ 验收表 → 源码；**单包项目**：README / 架构文档 → 验收表 → 源码
2. 演进记录：决策记录或偏差节（如「偏差 N：现象 / 判断 / 修复」），git log 只作语义补充；项目没有这类记录就跳过，不硬找
3. 编号体系：项目自定义的决策号与验收号（如决策 `A1/A4`、验收 `AC-*`），核对代码落实情况时逐条对照；编号含义以项目术语表为准

## 行为验证隔离纪律

- 外部工具的本地配置可能含真实凭据（如 `~/.<tool>/config.json`），梳理/验证时配置目录必须指向临时目录（如 `--agent-dir` 指向 temp），禁止读真实配置
- 验证 key 不落命令历史、不入 git；用完删除
- 伪 TTY 验证用管道 + EOF（如 `printf "xxx\n/exit\n" | <tool> --offline`），不用 script 命令包裹

## 文档落点约定

- 演进时间线 → 项目已有的演进史/决策记录章节；没有就并入决策记录，不建独立文档
- 模块技术细节 → 就近设计文档（包级 DESIGN.md，若有）
- 过时核对结果 → 原文修正，不另立文档
- 与结论无关 → 丢弃

## 技术细节粒度

值得写进文档的细节：机制与取舍、数据结构、边界情况、依赖与版本约束。不写：逐行注释式描述、显而易见的内容。

## 调研纪律（沿用 topic-research）

- 证据等级：S 级（源码逐行读）、A 级（官方文档/依赖清单/仓库结构）、B 级（行为观察）
- 无证据就是推断；推断必须标注
- 文档已写入的结论被代码推翻时，先改文档再说明
