# 视觉证据矩阵

> 用于游戏/UI 的截图、contact sheet、前后对比。具体分辨率、场景、相机由项目规范给出。

## 1. 证据类型

| 类型 | 能证明 | 不能证明 |
|---|---|---|
| 单张截图 | 可读性、剪影、布局 | 连续动作、时序、手感 |
| 前后对比 | 改动是否可见 | 规则是否正确 |
| 多分辨率截图 | 布局不破版 | 性能、输入延迟 |
| contact sheet | 多状态并排 | 真实游玩节奏 |
| 固定步长定格 | 接触帧/阶段 | 视觉连续观感 |
| 录屏/试玩 | 连续观感、节奏 | 规则边界 |

## 2. 截图前置

- 固定场景、固定相机、固定角色状态
- 固定 UI 数据（HP/架势/进度/提示）
- 固定分辨率与窗口模式
- 等待布局/渲染完成再截
- 记录实际输出尺寸与版本/commit

## 3. 矩阵

| 维度 | 至少覆盖 |
|---|---|
| 分辨率 | 设计基准 + 最小支持分辨率 |
| 屏幕 | 正常/暂停/失败/胜利/空状态 |
| 战斗状态 | 待机/起手/命中/受击/死亡 |
| 设备/输入 | 键鼠/手柄提示（如适用） |
| 主题/亮度 | 亮/暗或灰度可读性（如适用） |

## 4. 断言与截图

- 能用数值断言的（边界/重叠/字号/间距）先断言，截图做补充。
- 截图不替代规则断言；断言不替代连续观感。
- 失败截图保留，不覆盖旧证据。
- 证据命名包含：状态、分辨率、版本/commit。

## 5. 评审

- 先看失败/边界，再看正常态
- 对比改动前后，避免只看新图
- 记录「看到什么/期望什么/差异」
- 结论写清证据层级
