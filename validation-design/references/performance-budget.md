# 性能预算与测量

> 具体 FPS、draw call、primitive、内存上限由项目规范给出；本表只定义预算维度与验证方法。

## 1. 预算维度

| 维度 | 说明 |
|---|---|
| 帧时间 | 平均/ P95 / 最差帧 |
| CPU | 主线程/物理/脚本/AI |
| GPU | draw call、primitive、overdraw、带宽 |
| 内存 | 纹理/网格/音频/峰值 |
| 加载 | 冷启动/场景切换/首帧 |
| 平台 | 桌面/主机/移动/浏览器 |
| 分辨率 | 设计基准/最低/高 DPI/4K |
| 温度/耗电 | 移动端持续负载 |

## 3. 测量协议

- 固定场景/固定相机/固定输入
- 记录设备、渲染器、分辨率、版本/commit
- 预热后采样，区分冷启动
- 多场景：战斗/UI/加载/最坏情况
- 保存原始数据，不只截图

## 4. 回归

- 预算进合并前检查（至少警告）
- 性能回归与功能回归分开
- 阈值变更要记录原因
- 移动端/低端机单独档位
- 不把一次快照当长期结论

## 5. 证据

- 结构：预算表、场景/设备矩阵
- 自动：帧时间/draw call/内存采样
- 主观：手感/卡顿/温度/耗电
- 结论写清「证明的是预算还是体验」
