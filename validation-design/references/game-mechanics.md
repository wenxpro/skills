# Profile — 游戏机制验证

> 这是 `validation-design` 的游戏领域 profile，不是通用规则。具体数值和项目规则写进项目文档。
> 测试层、fixture、dummy、场景矩阵与 testbed 规范见 `gameplay-testing.md`；本 profile 只写验证对象与证据。

## 常见验证对象

| 对象 | 模型假设示例 | 失败判据示例 |
|---|---|---|
| 战斗模型 | 不同兵种应产生不同节奏/角色，而不是只比攻击力 | 去掉克制或改同频率后，结果/打法完全不变 |
| 经济模型 | 来源与消耗应形成取舍，而不是单一最优 | 所有资源都投入同一项仍最优 |
| 成长模型 | 成长应改变打法，而不是只放大数值 | 成长前后选择分布不变 |
| 对局地图 | 优先旋转对称（默认 180°）；双方路线/掩体/到点距离等价；PvE 也按 PvP 公平性验证 | 一方有更短/更安全路线；双路线造成不公平 |
| 战斗/目标决策 | 当前局势下有唯一最优解/次优代价；换局势会变化（判据见 `level-encounter-design`） | 多个等价选项，无法验证选择 |
| AI | AI 应制造可归因压力，而不是随机送/锁血 | 输赢无法归因到 AI 行为 |

> 对局地图先保证公平：优先旋转对称（默认 180°）、单主通道也可；不要为了“有选择”加第二条不等价路线。关卡/遭遇设计判据见 `level-encounter-design`。

## 证据层级

| 层级 | 能证明 | 不能证明 |
|---|---|---|
| 静态预览/截图 | 可读性、信息层级 | 手感、决策、平衡 |
| 规则模拟 | 公式、TTK、资源曲线、极端情况 | 真人选择、学习曲线 |
| Bot 对战 | 策略空间、压力分布 | 玩家乐趣、理解成本 |
| 真人试玩 | 理解、选择、想再来 | 大样本平衡、长线留存 |

## 战斗模型

战斗模型的角色差异化、攻击时间轴、TTK、克制预算、对决矩阵与反事实检查，见 `game-combat-model`；本 profile 只负责验证设计，不重复模型方法。

## 审计问题

- 这个验证是在测“参数”还是“决策”？
- 对局地图是否优先旋转对称（默认 180°）？双方路线/掩体/到点距离是否等价？PvE 是否按 PvP 标准？
- 如果首个可玩切片只有单主通道，是否验证了目标/交战选择，而不是硬造第二路线？
- 目标/交战选择是否定义了当前局势下的最优解/次优代价？
- 最优解是否会随敌方位置/兵力/计时变化？如果永远不变，策略已被解开。
- 1v1 自动对砍能否证明兵种角色？如果不能，结论是否写清范围？
- 有没有去掉克制/改频率的对照？
- 试玩问题是否只问“知不知道克制”，而没问“打法是否不同”？
- 失败结果是可归因的，还是只记录“输了”？
