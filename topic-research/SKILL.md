# 课题调研

调研的目标是「结论可信、可复核、可写进文档」。调研失败通常是三种原因：只看局部没看全景、先有结论再找证据、证据等级不清。

> 个人/团队偏好（调研入口、证据标注格式、文档落点约定）在 `standards.md`，其他团队可整体替换。

## 何时使用

- 新领域/新技术栈调研（如「终端 UI 生态现状」）
- 竞品或开源项目拆解（如「某 agent 项目的 TUI 怎么做」）
- 技术选型前的备选方案考察（如「自研还是引库」）

单点查证（某个 API 怎么用、某个文件在哪）不用本流程，直接查。

## 操作顺序

1. 界定课题
2. 建生态全景（先全景后深入）
3. 逐点深入，多入口交叉验证
4. 假设与验证分离
5. 证据分级标注
6. 输出结论

## 第一步：界定课题

动手前回答四个问题并写下来：

1. 调研要回答什么决策问题？（如「渲染引擎自研还是引库」）
2. 结论写进哪里、给谁看？（文档章节、读者水平）
3. 证据等级要求？（选型决策需要依赖清单/源码级证据；背景介绍可用官方文档级）
4. 时间盒？（防止在单点上无限深入）

课题没界定清楚就开始搜，是调研走偏的第一原因。

## 第二步：建生态全景（先全景后深入）

**顺序不可颠倒**：先看全景，再深入任何单点。只看一两个项目就下结论，等于用个例代表全局。

全景入口（按优先级）：

1. GitHub topics：按 star 排序看生态全貌，识别框架层/应用层/工具层（接口方式见 `standards.md`「调研入口偏好」）
2. awesome 列表（`awesome-<主题>`）：社区整理的事实标准清单
3. 官方文档站点的生态页（ecosystem / getting started）
4. 包管理器搜索（npm / crates.io / pypi）：同一主题的下载量排行

全景输出的形态：按语言和层级（框架、组件、应用、工具）归类的事实标准表。**框架层与应用层要分开**——应用用了什么栈，不等于生态里有什么框架。

全景建立前，不读任何单项目的源码。

## 第三步：逐点深入，多入口交叉验证

深入单个项目时，每个关键事实至少两个独立入口交叉验证。可用入口按可信度排序：

| 等级 | 入口 | 能回答什么 |
|---|---|---|
| 源码 | 本地 clone 后读（优先），或 GitHub API 列目录/文件 | 真实实现、文件规模、模块划分 |
| 依赖清单 | package.json / Cargo.toml / pyproject.toml | 技术栈（最可靠的技术栈证据） |
| 官方 README / 文档 | 仓库根或 docs/ 目录 | 定位、能力边界、用法 |
| 行为观察 | 本地安装并运行产品 | 交互表现、实际体验 |
| 社区文章 | 博客、issue、讨论 | 背景、动机、历史 |

技术栈判定规则：**以依赖清单 + 源码结构为准**。topics 标签、language 字段、star 数等仓库元数据可能过时或标错，只能当线索、不作证据；README 的自我定位也以依赖清单复核为准。

反例（本 skill 的教训来源）：仅凭包名与目录结构推断技术栈、未读 README 就下结论，被验证推翻（案例细节见 `standards.md`「调研纪律」）。推断不等于验证。

## 第四步：假设与验证分离

调研前基于直觉写下假设（明确标为「假设」），然后为每条假设安排验证动作：

- 假设必须能证伪：想清楚「如果它是错的，什么证据会出现」
- 验证不过就修正假设，不硬撑、不找支持性证据
- 特别警惕「先有结论再找证据」：结论应由证据推出，不是由立场推出

自查问题：这句话是我调研前就想好的，还是证据推出来的？

## 第五步：证据分级标注

写进文档的每个关键事实，标注证据等级与日期：

- **S 级**：本地源码逐行读
- **A 级**：官方文档 / README / 依赖清单 / 仓库结构（GitHub API 列目录实测）
- **B 级**：行为观察（运行产品）
- **C 级**：社区文章、issue、讨论

标注格式（本项目约定见 standards.md）：结论后括号注明实测方式与日期。**未验证的推测必须显式标「推断/未验证」**，不允许无标注的推测混进结论。

## 第六步：输出结论

输出三部分，事实与判断分写：

1. **事实清单**：每个事实带证据等级与日期，读者可复核
2. **对决策的影响**：事实到结论的推理链，明确哪些是推断
3. **建议**：基于影响的行动建议，含备选路径

输出前自查：每个结论能否回答「我怎么知道的？证据是什么？什么时候查的？」。答不上来的，回去补验证，或降级为推断。

超出时间盒的课题：先输出已完成结论并标注未覆盖范围，剩余点列为后续调研项，不在本次继续深入。
