# 反馈 runbook

> 只写顺序、输入输出和交接点；具体规则仍由各 skill 负责。

## 1. 收集证据

- 证据可复核：日期、版本、样本、命令、日志/报告位置。
- 区分事实、判断和推断。
- 失败、跳过、样本不足都记录。

## 2. 分类

| 类别 | 去向 |
|---|---|
| 通过 | 更新验收状态 |
| 失败 | 修复或重新设计 |
| 偏差 | 记录范围、影响、owner |
| 过时 | `docs-audit` / `docs-core` 修正或归档 |
| 需要决策 | `review` |

## 3. 更新状态

用 `implementation-track` 更新验收状态与偏差；历史证据保留当时结论，当前状态用最新实测。

## 4. 回流

```text
文档漂移 → docs-audit / docs-core
设计/范围/取舍变化 → review → design-stage
版本/优先级/下一期 → roadmap-planning
需要修复 → delivery-stage
```

## 5. 出口

至少留下：

1. 证据范围与来源。
2. 通过/失败/偏差/过时清单。
3. 验收状态更新。
4. 文档修正或待修正项。
5. 待评审决策与回流点。
6. 未关闭项与 owner。

## 6. 停止条件

- 证据不可复核，无法判断通过或失败。
- 借反馈直接改设计结论。
- 只报通过项，隐藏失败或样本不足。
- 行动项没有 owner 或下一步。
