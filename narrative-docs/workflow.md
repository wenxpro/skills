# 工作流

按任务选一节，不要一次读全部。模板都在 `references/templates/`。

## 1. 初始化项目文档

适用：新长篇 / 剧本立项；已有文档散、过时、不可维护。

先问，不要猜：目标路径、项目名、形式（线性剧本 / 分支剧本 / 小说 / 视觉小说）、预计长度、目标读者、当前阶段（N0~N4）。

1. 检查目标目录：`docs/` 已存在且非空时，先读 `00-README.md`，问用户覆盖 / 合并 / 换目录；不要默认覆盖。
2. 复制 `references/templates/` 到目标文档目录（默认 `docs/`），或只复制当前阶段需要的文件。
3. 填 `00-README.md`：项目一句话、当前阶段、阅读顺序、文件状态。
4. 填 `01-story-brief.md`：一页纸；只写已确定的内容，未知标 `assumption`。
5. 如有关键方向（POV、结局、分支模型、形式），写 `10-adr/0001-<slug>.md`。
6. 自检：`11-checklists/checklists.md` 的“初始化”一节。
7. 停止：01 未被作者确认前，不写 02~07。

完成标准：00/01 存在；01 能在一页内说清“这个故事是什么、对谁承诺什么、当前不做什么”；关键方向有 ADR 或明确待定。

## 2. 写 / 更新 Story Brief

适用：新项目；故事方向变了；试读后发现承诺不清。

1. 写一句话（logline）：谁想要什么、阻碍是什么、代价是什么。
2. 写主题问题：故事在追问什么；不要写成道德结论。
3. 写读者承诺：读者应获得的体验（悬念 / 情感 / 智性 / 恐惧等），最多 3 条。
4. 写范围：当前阶段写到哪里、不写什么；未来内容放“开放问题”。
5. 写读者体验判据：试读时要观察什么，不写“好看”。
6. 写止损条件：什么现象说明方向不成立。
7. 自检：一页内；没有完整大纲；没有未标注的假设。

不要把：一句话写成剧情梗概；把主题写成说教；把“很多人喜欢”当承诺。

## 3. 世界与人物

适用：N1 结构阶段；当前幕需要新设定；人物行为说不通。

1. 只写当前幕需要的世界规则；每条写“能做什么 / 不能做什么 / 代价”。
2. 区分 `canon`（已确定）与 `assumption`（待验证）；不要把草稿想法写进连续性台账。
3. 人物卡写欲望、恐惧、秘密、缺陷、弧线、说话方式；配角可以只写一行。
4. 写关系与知识状态：谁认识谁、谁知道什么、什么时候知道。
5. 写术语与称谓：谁在什么场合怎么称呼谁。
6. 自检：每条设定能影响一个场景或选择；没有“百科式”堆料。

不要把：人物小传写成履历；设定写成规则书；把作者知道的信息当成人物知道的信息。

## 4. 结构与场景卡

适用：N1~N2；大纲转场景；分支剧本设计选择。

1. 选结构：幕 / 序列 / 场景；线性或分支；先写主路径。
2. 每场写：目标、阻碍、转折、选择、后果；没有转折的场景合并或删。
3. 写揭示表：什么时候给读者什么信息；谁先知道。
4. 分支剧本写：选择 ID、选项、flag、汇合点、死局检查。
5. 写节奏：紧张 / 缓和 / 信息密度；不要连续高强度的同一种场景。
6. 场景卡只写工作信息，不写正文；正文另存。
7. 自检：每场都能回答“如果删掉，故事少了什么”。

不要把：场景卡写成小说片段；把选择写成换台词；分支写成互不影响的平行线。

## 5. 初稿

适用：结构确认，开始写正文。

1. 以场景卡为工作假设，不把它当锁死的规则；发现更好的转折先改卡，再写正文。
2. 每写完一场，更新连续性台账：时间、地点、人物、物件、知识状态、flag。
3. 人物说话不符合语气指南时，先判断是人物变了还是指南过时。
4. 不在初稿阶段追求句子完美；先把事件与选择写清楚。
5. 自检：场景目标是否达成；转折是否发生；后果是否留下痕迹。

## 6. 试读 / 编辑评审

适用：一个完整段落 / 一幕 / 全稿可读；准备外部试读。

1. 准备：版本号、试读范围、读者画像、时长；不提前讲解。
2. 只观察：读者在哪里停、哪里困惑、哪里预测、哪里失去兴趣。
3. 问 3~5 个问题：故事讲什么？主角想要什么？哪里最想停？哪里不信？会继续读吗？
4. 记录原话与场景 ID，不只写总结；不辩护设计。
5. 对照 `08-readthrough.md` 的判据：理解、情绪、agency、转折、连续性、分支收敛。
6. 提炼：3 条观察、3 条问题、3 条行动；行动对应场景 / 人物 / 连续性 ID。
7. 判断止损：读者说不出主角动机、连续 3 人同一处困惑、分支出现死局、情绪节点无铺垫——先改结构，不加内容。

不要把：把“读者没看懂”解释成“读者水平不够”；用一次自读代替试读；只收集夸奖。

## 7. 修订

适用：试读 / 编辑意见回来；准备下一版。

1. 在 `12-revision-log.md` 建本轮记录：版本、日期、来源、问题、改动、影响文件。
2. 分类：故事承诺 / 结构 / 人物 / 连续性 / 语气 / 文字。先修 P0。
3. 一次只改一类问题；不要边改结构边润色。
4. 改完回写：场景卡、连续性台账、人物知识状态、分支表。
5. 对比版本：哪些问题消失、哪些仍在、哪些新引入。
6. 自检：`12-revision-log.md` 与文档一致；受影响场景重新试读。

不要把：把所有意见都改一遍；只改正文不改设定；用润色掩盖结构问题。

## 8. 变更与维护

适用：改世界规则 / 人物 / 结构 / 分支；文档与正文不一致。

1. 定位影响面：受影响的场景、人物、连续性条目、分支、读者承诺。
2. 先改规则文档：世界 / 人物 / 结构 / 语气 / 连续性。
3. 再改正文：规则与正文不一致 = 没改完。
4. 判断是否要 ADR：POV、结局、分支模型、形式、核心世界规则 → 新 ADR；纯文字润色 → 不需要。
5. 更新试读判据：故事承诺变了，原来的判据可能失效。
6. 自检：`11-checklists/checklists.md` 的“变更”一节。

不要把：只改正文不改设定；用“小改动”跳过连续性；把已废弃的设定留在 canon 里。
