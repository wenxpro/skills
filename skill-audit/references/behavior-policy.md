# 主动行为与干预策略审计

> 适用于会主动提示、打断、建议切换/停止/提交的 skill。纯参考型 skill 也要声明「无主动行为」。

## 为什么单独审

结构、description 和触发句只能证明「skill 会被调用」，不能证明「调用后的多轮行为正确」。

常见问题不是内容错，而是策略缺失：

- 每轮都提示，变成打扰
- 用户拒绝后继续追问
- 信息不足时直接建议新开/提交
- 旧 handoff 当当前事实
- 该提示切换时不提示

## 审计问题

1. 这个 skill 会主动提示、打断或建议用户行动吗？
2. 触发条件是否可观察（事件、状态、用户输入）？
3. 「不触发」的条件是否写清？
4. 频率上限是什么？每个任务最多几次？
5. 用户拒绝后怎么办？什么时候可以再提？
6. 信息不足时是继续、追问还是停止？
7. 状态过期、新会话误读摘要时怎么办？
8. 有没有「不行动」的默认路径？
9. 是否会把临时推理、聊天记录、旧摘要当事实？
10. 有没有多轮行为验收用例？

## 常见缺陷

| 类型 | 表现 | 修复 |
|---|---|---|
| 过度提示 | 每轮都建议新开/提交/切换 | 加边界、频率、拒绝后规则 |
| 提示不足 | 该切换时不提示 | 加必须触发条件 |
| 拒绝后重复 | 用户说「继续」仍反复追问 | 记录拒绝，直到下一边界 |
| 信息不足乱建议 | 没有 handoff 就建议新开 | 先补状态，再判断 |
| 旧状态当新状态 | 过期 handoff 继续用 | 标 `Superseded`，先验证 |
| 主动行为无出口 | 提示后没有选项或默认 | 给「继续/切换/停止」选项 |
| 被动 skill 假装主动 | 参考型 skill 频繁打断 | 明确「无主动行为」 |

## 多轮验收

单句触发用例之外，至少覆盖：

- 提示后用户接受 → 执行切换/交接
- 提示后用户拒绝 → 不重复提示，直到下一个工作包边界
- 信息不足 → 先补状态，不直接建议切换
- 新会话拿到 handoff → 先复述、再验证
- handoff 过期 → 标 `Superseded`，不继续引用
- 连续多轮无新证据 → 停止循环，升级为阻塞或换策略

## 输出

沿用 `skill-audit` 的三组报告：

- **必须改**：主动行为没有触发/频率/拒绝后/降级规则
- **建议改**：提示话术不清晰、缺少多轮用例
- **核对无误**：列出检查过的主动行为与默认路径
