# 设计 runbook

> 只写顺序、输入输出和交接点；具体规则仍由各 skill 负责。

## 1. 界定问题

- 问题、范围、明确不做。
- 约束、决策人、时间盒。
- 判断是否需要跨项目：两个以上仓库/团队共同交付时，加 `cross-project-integration`。

## 2. 收集输入

| 需要 | 使用 |
|---|---|
| 外部事实、竞品、技术选型 | `topic-research` |
| 现有代码、架构、演进 | `code-digest` |
| 文档健康度 | `docs-audit` |
| 当前验收状态与偏差 | `implementation-track` |

只读与当前问题相关的部分；外部事实与代码事实分开标注。

## 3. 选轨道

| 轨道 | 产出 | Skill |
|---|---|---|
| 体验架构 | 表面、导航、状态所有权、生命周期 | `experience-architecture` |
| 职责设计 | 上下文、模块所有权、依赖方向、接口 | `responsibility-design` |
| 跨项目协作 | 上下游、接口登记、依赖矩阵、集成计划 | `cross-project-integration` |
| 文档规则 | 行为规则、验收、ADR、文档槽位 | `game-docs` / `docs-core` |

小问题不必全开；跨模块、跨表面、跨项目、持久状态变化必须收敛。

## 4. 图与决策

按风险选最小图集：

- 上下文/组件图：边界、所有权、静态依赖。
- 生命周期状态图：创建、注册、结束、清理。
- 时序图：多条创建路径、跨上下文事件、失败/清理路径。
- 所有权/生命周期表：所有动态对象。
- 决策锁、Pre-mortem、Kill Criteria：不可逆决定。

## 5. 评审与规划

1. 方向、范围、架构、体验变化交 `review`。
2. 评审通过后交 `roadmap-planning` 排期。
3. 规划输出 M/W 映射、下一包、待决问题。

## 6. 出口

至少留下：

- 设计问题、范围、约束。
- 采用的事实与输入。
- 各轨道实际产物。
- 关键决策与未决问题（带 owner）。
- 验收种子与实现工作包。
- 评审结论或待评审状态。

## 7. 停止条件

- 关键输入缺失，且无法标注为推断。
- 不可逆决定没有最小验证或回滚条件。
- 跨项目接口没有 owner 或冻结点。
- 评审未通过，或未决项没有 owner。
