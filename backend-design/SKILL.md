# Backend Design

设计后端服务的运行时结构与风险边界。文档写到 `software-docs` 定义的槽位；本 skill 负责设计方法、检查表与模板。

## 何时使用

- 新服务、新 API、新数据模型
- 现有服务要补架构、接口、数据、安全或可靠性设计
- 需要做威胁建模、容量评估、故障模式分析
- 准备设计评审或上线评审
- 跨团队接口需要先定清楚再登记

不适用：

- 代码模块/依赖边界 → `responsibility-design`
- 跨仓库接口登记与集成计划 → `cross-project-integration`
- 代码审查与合并前检查 → `code-review`
- UI/前端基线 → `ui-baseline`
- 文档槽位与模板 → `software-docs`
- 纯排期 → `roadmap-planning`

## 核心原则

1. **先所有权，后接口。** 谁拥有哪份状态、谁能写、谁只能读，先定清楚；接口只是所有权的投影。
2. **接口先于实现。** 错误、幂等、分页、版本、鉴权、限流在编码前定；不要用实现倒推约定。
3. **故障模式优先。** 超时、重试、重复、丢失、部分失败、顺序错乱都要在设计里出现。
4. **数据有生命周期。** 创建、读取、更新、删除、保留、导出、PII 处理与备份恢复都要写清。
5. **最小权限与信任边界。** 每个调用方只拿完成任务所需的权限；边界两侧分别校验。
6. **没有测量就没有目标。** SLO、容量、延迟目标必须能测量、能归因。
7. **迁移可逆。** 优先 expand → migrate → contract；不可逆迁移必须有回滚条件与演练。

## 主动行为

本 skill 为参考型，不主动打断或提示；用户请求后端/服务设计时按流程执行。信息不足时先问约束、SLO、数据与合规要求，不猜。

## 设计顺序

1. **框架**：用户、场景、SLO、约束、非目标、不可逆决定。
2. **架构（运行时）**：上下文、容器/组件、依赖方向、部署拓扑、故障域、容量假设；代码模块边界另用 `responsibility-design`。
3. **接口**：命名、错误、分页、幂等、版本、鉴权、限流、超时。
4. **数据**：所有权、schema、键与索引、事务/一致性、迁移、保留、PII。
5. **安全**：资产、角色、信任边界、威胁、缓解、剩余风险。
6. **可靠性**：超时/重试/熔断、降级、可观测性、备份恢复、运行手册。
7. **评审与验收**：用 `review` 的软件/架构 profile；按风险追加安全/数据/SRE 角色；验收引用 `docs-core/references/acceptance-taxonomy.md`。

## 设计检查

| 领域 | 必须回答 | 详见 |
|---|---|---|
| 架构 | 边界在哪、谁依赖谁、部署在哪、哪个单点、故障影响多大 | `references/architecture.md` |
| 接口 | 成功/失败长什么样、能否安全重试、怎么升级、谁有权调用 | `references/api.md` |
| 数据 | 谁拥有、主键/索引、事务边界、一致性窗口、怎么迁移、保留多久 | `references/data.md` |
| 安全 | 资产、角色、信任边界、主要威胁、缓解与剩余风险 | `references/security.md` |
| 可靠性 | SLI/SLO、超时、重试、熔断、降级、告警、恢复 | `references/reliability.md` |

## 评审与风险角色

高风险项按需追加角色；不是每个设计都要全套。

| 触发 | 追加角色 | 关注 |
|---|---|---|
| 认证、支付、PII、对外接口 | 安全 | 越权、泄露、重放、密钥 |
| schema 变更、迁移、一致性 | 数据 | 不可逆迁移、锁表、校验 |
| SLO、容量、故障恢复 | SRE/运维 | 单点、备份、回滚、告警 |
| 公开接口、多版本、弃用 | API owner | 兼容、弃用窗口、调用方 |

## 验收

- 验收类别：`AC-SEC`、`AC-PERF`、`AC-REL`、`AC-DATA`、`AC-COMPAT`、`AC-OPS`，加功能与 UI 项。
- 每个高风险项至少一个验收用例；证据类型必须写明。
- 无证据的非功能项只能「有条件通过」或「待补证据」。
- 证据放 `docs/10-evidence/`，评审记录放 `docs/09-reviews/`。

## 模板

- `templates/service-design.md` — 一页服务设计：边界、接口、数据、失败、开放问题
- `templates/threat-model.md` — 资产、角色、信任边界、威胁与缓解
- `templates/api-design.md` — 单个接口的请求/响应、错误、幂等、鉴权、版本

## 边界与交接

- 文档槽位与文件：`software-docs`
- 代码模块/依赖/状态边界：`responsibility-design`
- 跨仓库接口登记：`cross-project-integration`
- UI/前端：`ui-baseline`
- 设计阶段：`design-stage`
- 评审：`review`
- 交付：`delivery-stage` / `execution-loop`
- 验收状态：`implementation-track`

## 反模式

- 先写代码再补接口文档
- 有重试但没有幂等
- 有迁移但没有回滚与校验
- 安全只在最后加一个检查表
- SLO 写了但没有测量方式
- 数据表没有 Owner，多个服务直接写
- 把跨仓库的接口登记塞进本项目架构文档
- 用「后续优化」代替容量与故障设计
