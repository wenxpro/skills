# 游戏音频

目标：让声音**可路由、可调、可持久、可测试**，而不是把音量全部塞在 Master 上。

本 skill 负责音频架构与混音规则；引擎音频 API/播放器实现用 `godot-game-runtime`，打击反馈的音效分层用 `game-feel`，音乐创作与编曲不在范围内。

## 何时使用

- 新建游戏音频总线、SFX/Music/Ambience 路由
- 接入占位音、运行时合成音、循环音乐
- 设计音量/静音设置、持久化、实时生效
- 排查「有声音但滑条没用」「切场景音乐断」「headless 报音频错」「声音叠成噪音」

不适用：

- 编曲、音色设计、母带处理 → 项目音频资产/音频设计师
- 引擎音频 API、headless、引擎持久化实现 → `godot-game-runtime`
- hitstop/震屏/闪白/震动预算 → `game-feel`
- UI 滑条布局/无障碍 → `ui-baseline`

## 行为

参考型 skill，无主动打断。用户要求音频架构/混音/设置时使用。

## 核心规则

### 1. 先定总线，再接声音

- 至少区分 Master、SFX、Music；需要时加 Ambience/UI/Voice。
- 每个播放器显式指定总线；不依赖默认 Master。
- 总线发送关系写清；分组音量不应互相覆盖。
- 总线命名稳定；代码、设置、测试使用同一套键。

### 2. 声音职责分层

| 层 | 例子 | 不该做 |
|---|---|---|
| UI | 确认/返回/滑条 | 抢战斗提示音 |
| 起手/预告 | 攻击类型提示 | 提前于动画/规则 |
| 命中/防御 | 命中、弹反、格挡 | 覆盖视觉可读性 |
| 环境/音乐 | 循环、氛围 | 压过关键提示 |
| 胜负/结算 | 胜利、失败 | 延迟到玩家失去反馈 |

同类事件用同一层；不同层不要共用一条容易失控的总线。

### 3. 运行时合成音是占位，不是最终资产

- 合成音要有明确采样率、位深、包络、噪声比例；结果可复现。
- 循环音频要保证接缝无爆音；频率/周期设计成整数循环。
- 占位音要标注「占位」；正式资产替换时保持事件名/总线不变。
- 合成失败/缺资产要静音或 fallback，不要崩溃。

### 4. 混音先留 headroom

- 单个音效不削顶；多个同时播放不爆音。
- 用总线音量做整体平衡，不用每个 clip 随机改增益。
- 关键提示音优先于环境/音乐；必要时 ducking。
- 音量滑条用线性/分贝转换集中处理；0 不等于静音总线，静音单独处理。
- 默认值写进项目规范；不把「听起来差不多」当默认。

### 5. Voice 管理与限流

- 固定 voice 池或最大复音数；满了用优先级/最旧替换。
- 高频事件有冷却/最小间隔；避免机关枪式叠音。
- 同一事件短时间重复要降低音量/变调或跳过。
- 空间化/衰减按项目需要；2D UI 音不参与 3D 衰减。

### 6. 设置与持久化

- 每个总线有音量；主静音独立于分组音量。
- 修改立即应用；保存只存用户偏好。
- 读取有默认值；缺文件/缺键不崩。
- 测试用独立配置，不读真实用户配置。
- 设置菜单的滑条/图标/无障碍由 `ui-baseline` 负责，音频层只提供值。

### 7. headless 与测试

- headless 不创建音频播放器/不依赖音频设备。
- 测试断言总线存在、播放器路由、音量/静音应用，不依赖「能不能听见」。
- 主观看感/音量平衡需要真人试听；不能只用截图或断言证明。
- 音频事件与 contact 帧对齐由 `game-feel` 定义。

### 8. 证据

- 结构证据：总线表、路由表、设置键、默认值。
- 自动证据：总线索引、播放器 bus、音量/静音断言。
- 主观证据：真人试听、不同设备/耳机/扬声器。
- 结论要写清「证明的是路由/设置，还是听感」。

## 检查清单

- [ ] Master/分组总线定义清楚，播放器显式路由
- [ ] 总线命名在代码、设置、测试中一致
- [ ] 单音不削顶，多音不爆音，关键提示优先
- [ ] 合成音可复现，循环接缝无爆音
- [ ] voice 池/复音上限/高频冷却明确
- [ ] 音量/静音实时生效，保存/读取有默认值
- [ ] headless 不创建音频依赖
- [ ] 自动断言覆盖路由/音量/静音，不冒充听感
- [ ] 真人试听覆盖设备差异
- [ ] 占位音标注，替换不改变事件名/总线

## 输出

- 总线/路由检查：`references/audio-bus-checklist.md`
- 音频目录/安全应用：`references/audio-catalog.md`
- 音频规格模板：`templates/audio-spec.md`
- 结论分层：结构/自动/主观

## 反模式

- 所有声音走 Master，滑条只有一个
- 播放器不指定总线，设置改总线但播放器还在 Master
- 每个 clip 单独改增益，整体还是爆音
- 循环音频接缝有爆音/静音缝
- 音量 0 当静音，主静音又单独覆盖
- headless 仍创建播放器，测试依赖音频设备
- 用截图/断言证明「听感好」
- 占位音直接当正式资产，没有替换计划

## 交接

- 引擎音频 API/播放器/headless/持久化 → `godot-game-runtime`
- 打击反馈/音效分层预算 → `game-feel`
- UI 滑条/设置菜单/无障碍 → `ui-baseline`
- 项目音频规范/验收 → `game-docs`

## 边界

- 不写具体项目总线名、音量值、音效文件名
- 不替代音乐创作、引擎 API、UI 规范
- 不把主观听感写成通用规则
- 占位音与正式资产的差异必须标注
