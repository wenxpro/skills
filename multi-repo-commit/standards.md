# 多仓库提交偏好

本文件存放 `multi-repo-commit` 中依赖个人/团队习惯的部分，可整体替换。

## 提交顺序

默认按依赖排序：

1. 共享库 / 规范 / schema
2. 使用方代码
3. 文档 / 示例 / 变更记录

如果文档描述的是本次代码行为，文档可以跟随代码仓库，或紧接其后提交。

## 提交粒度

- 一个仓库一个主题；一个主题可以拆多个提交
- 不在一个提交里混入多个仓库
- 不把格式化、依赖升级、业务变更混在一起
- 用户未提交的文件不默认纳入；只暂存明确路径

## 凭据

- 不同域名优先用 SSH key，按 host 配置
- HTTPS 使用 credential helper；不要把 token 写进 remote URL
- 一个任务内可以顺序推送多个仓库，但每个仓库使用自己的 remote/凭据
- 认证失败先验证 `ssh -T <host>` 或 credential helper，不要盲目重试

## 汇报

每个仓库至少记录：

- 分支
- commit hash
- push 结果
- 远端 `ls-remote` 验证
- 未提交文件/未完成项

部分失败时，只重试失败仓库，并保留已成功仓库的记录。

## 跨仓库引用

- 同一个任务编号/ADR 写进各仓库提交信息
- 依赖版本记录 commit hash，不只写“最新”
- 文档引用代码提交时，写清 commit 或版本
