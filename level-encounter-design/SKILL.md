# 关卡与遭遇设计

目标：地图和遭遇必须**改变玩家的决策**；不能只是背景或数值堆叠。

本 skill 负责目标、路线、出生、掩体、视野、节奏与公平性；纯 UI 布局用 `ui-baseline`，屏幕/导航用 `experience-architecture`。

## 何时使用

- 对局地图、出生区、据点/目标、路线、掩体、低墙
- 遭遇战组合、接战角度、撤退路径、节奏
- 地图公平性、对称性、可读性
- 关卡/遭遇的验证场景

不适用：

- 纯 UI 布局/组件规范 → `ui-baseline`
- 产品屏幕/导航 → `experience-architecture`
- 完整 Spec/验收 → `game-docs`
- 纯地形美术 → 不在本 skill

## 行为

无主动打断。用户要求设计/审计关卡与遭遇时使用；不主动评价日常美术或单次地图微调。

## 核心规则

1. **地图服务决策。** 每个目标/路线/掩体至少改变一个选择：去哪、先打谁、是否绕后、是否撤退。
2. **对局先公平。** 优先旋转对称（默认 180°）；双方到目标距离、掩体、路线等价；PvE 也按 PvP 标准。验证判据见 `validation-design`。
3. **首个可玩切片只做单一目标。** 一个中央据点足够；不要为了“有选择”加不对称第二路线。
4. **不做装饰地形。** 不改变路径/掩体/视野的障碍就删掉；否则只是噪音。
5. **时间可控。** 出生到目标、首次接战、单局时长要在目标区间。
6. **遭遇有反制。** 每个强势位置/组合要有代价、绕行或撤退路径；不能无解。
7. **可读性优先。** 目标、路线、掩体、接战方向要能从相机看清；颜色不是唯一信息。
8. **路线决策可验证。** 同一局势下有唯一最优选择；次优有明确代价；换局势最优会变化。验证方法见 `validation-design`。
9. **先单目标，再多目标。** 多据点/多路线要等单目标验证通过。

## 审计清单

- [ ] 地图是否优先旋转对称（默认 180°）？双方距离/掩体/路线是否等价？
- [ ] 每个障碍是否改变路径/掩体/视野？
- [ ] 是否存在一方独有捷径/掩体/高地？
- [ ] 出生到目标、首次接战、单局时长是否在目标区间？
- [ ] 强势位置/组合是否有代价、绕行、撤退？
- [ ] 目标/路线在相机下是否可读？
- [ ] 是否存在“只有一条永远最优”或“所有路线等价”？
- [ ] PvE 是否也按 PvP 公平性验证？

## 输出

- 地图 brief：`templates/map-brief.md`
- 对称性/节奏/路线检查
- 遭遇矩阵：组合、接战角度、撤退路径、反制
- 验证场景：`validation-design`

## 反模式

- 地图只是背景，不影响决策
- 一方更近/更安全/有独有掩体
- 为了“有选择”加两条不等价路线
- 低墙/障碍不改变任何路径
- 目标放在无解火力区
- 没有撤退路径
- 多据点/多路线过早引入

## 交接

- 测试/验证：`validation-design`
- 平衡：`game-systems-balance`
- 战斗模型：`game-combat-model`
- AI 行为/反制：`game-ai-design`

## 边界

- 不写项目具体坐标/数值；写项目文档
- 不替代 `game-docs` 的 Spec/验收
- 不做最终美术地图
