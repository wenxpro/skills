# 游戏机制测试设计

目标：用**最低可行测试层**回答验证问题；先隔离，再组合。

常见错误不是实现跑不起来，而是把移动、碰撞、攻击、AI 全塞进一个场景，出问题后无法归因。

本 skill 负责测试场景与 fixture 的设计；验证假设、指标和失败判据用 `validation-design`，战斗模型本身用 `game-combat-model`。

## 何时使用

- 验证移动、碰撞、避障、攻击、目标选择、AI、经济、关卡机制
- 设计 testbed / gym / 测试地图 / 假人 / 静态障碍
- 设计 scenario matrix、测试夹具、回归场景
- 判断一个测试是否引入了不必要的敌人/AI
- 规范“可行性验证”该看什么、该记录什么

不适用：

- 完整 GDD / Spec / 验收矩阵 → `game-docs`
- 代码审查 / 合并前检查 → `code-review`
- 纯 bug 修复
- 真人试玩执行与结果分类 → `feedback-stage`
- 战斗数值/角色模型设计 → `game-combat-model`

## 行为

无主动打断。用户要求设计/审计游戏机制测试时使用；不主动评价日常实现细节。

## 核心规则

1. **先选最低测试层。** 能用一个友军小队验证的，不要加敌人；能用静态假人验证的，不要加 AI。
2. **移动/碰撞默认无敌人。** 友军、静态障碍、边界、目标点足够；敌人会引入目标选择/攻击变量。
3. **攻击默认用 dummy。** 静止、不还手、有 HP 的假人足以验证射程、攻击循环、多队攻击槽位；完整 AI 只用于集成/决策。
4. **固定 fixture。** 固定地图、单位、假人、障碍、相机、tick、seed、初始位置；每次 reset。
5. **一次只改一个变量。** 本轮验证“后排被挡”就不要同时改攻击槽位、AI、据点。
6. **Scenario 用 Given / When / Then。** 前置、操作、预期必须可观察。
7. **指标先于结果。** 时间、到达率、卡住次数、进入攻击距离时间、抖动、失败原因。
8. **证据可复查。** 日志、位置轨迹、截图/录屏、sim 输出；不只看“感觉不卡了”。
9. **失败分类。** bug / 调参 / 设计问题 / 证据不足；不要把所有失败都归因到碰撞。
10. **低层通过后再升级。** L0/L1 通过再进 L2；L2 通过再进 L3；不要用 L3 的失败反推 L0。

## 测试层

| 层 | 场景 | 需要敌人？ | 能证明 | 不能证明 |
|---|---|---|---|---|
| **L0 移动** | 单队移动、停止、继续 | 否 | 输入→移动、速度、停止 | 碰撞、避障、攻击 |
| **L1 碰撞/避障** | 多友军同点、后排被挡、边界/静态障碍 | **否** | 友军碰撞、编队、绕行 | 攻击、目标选择、AI |
| **L2 攻击交互** | 静态 dummy：射程、攻击循环、多队同目标、dummy 死亡 | **dummy，不需要 AI** | 攻击距离、攻击槽位、转火 | 目标优先级、AI 决策 |
| **L3 集成** | 敌人 AI + 据点/地形/多单位 | 是 | 目标选择、抢点、组合、AI | 真人理解与乐趣 |
| **L4 真人** | 外部试玩 | 是 | 理解、选择、想再来 | 大样本平衡、长线留存 |

> 移动/碰撞验证不需要敌人；攻击验证需要目标，但不一定需要敌人 AI。

## Fixture / Testbed

一个可复用的测试场景至少固定：

- 地图与边界
- 相机角度/缩放
- 单位类型、数量、出生位置
- dummy 位置/HP/是否还手
- 静态障碍/低墙
- tick、seed、build
- reset 方式
- 场景选择入口（例如 `--scenario=M03`）

推荐一个 `TestLab`/`gym` 场景 + 场景参数，不要每次开完整对局。

## Scenario Matrix

每条场景写：

| 字段 | 内容 |
|---|---|
| ID | `M-03` / `A-02` |
| 层 | L0–L4 |
| 目标 | 这一条验证什么 |
| Given | 初始 fixture |
| When | 玩家/脚本操作 |
| Then | 可观察预期 |
| 指标 | 时间、次数、位置、卡住时长 |
| 通过 | 阈值 |
| 证据 | 日志/截图/轨迹 |

模板见 `templates/test-plan.md` 与 `templates/scenario-matrix.md`。

## 反模式

- 用带敌人的多人场景验证“后排会不会被前排卡住”——混入目标选择和攻击变量
- 一个场景同时验证移动、碰撞、攻击、AI、据点
- 用完整对局当单元测试
- 没有 reset/seed，结果不可复现
- 只截成功画面，不记录卡住/失败
- 没有指标，用“看起来没问题”通过
- 把 L3 的失败直接归因到碰撞/寻路
- 为了测试移动而加敌人、加 AI、加地形

## 交接

- 验证假设/指标/失败判据：`validation-design`
- 战斗模型设计：`game-combat-model`
- Spec/验收：`game-docs`
- 真人试玩与结果分类：`feedback-stage`
- 实现状态：`implementation-track`
- 代码审查：`code-review`

## 边界

- 不写项目具体数值；数值与场景写进项目文档
- 不替代 `game-docs` 的验收矩阵
- 不替用户执行真人试玩
- 只设计测试，不替用户拍板“通过/不通过”
