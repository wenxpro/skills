# Windows 与仓库卫生

> 适用于 Windows + PowerShell + Git 的开发环境。目标是避免编码损坏、行尾噪声与并行提交冲突。

## 1. 文本编码

- 默认 UTF-8；不要用会写入 BOM 的方式覆盖源码。
- PowerShell 5.1 的 `Get-Content`/`Set-Content` 可能按 ANSI 读取 UTF-8，导致中文损坏。
- 优先用编辑器/专用写入工具；必须用 PowerShell 时显式指定 UTF-8，并在写入后检查 BOM/字节。
- 修改后检查：文件开头是否出现 BOM、是否出现替换字符、diff 是否整文件重写。

## 2. 行尾

- 仓库可能启用 `core.autocrlf`；不要在编辑中无意把整文件从 LF 改成 CRLF。
- 大批量行尾变化会淹没真实 diff；提交前看 `git diff --stat` 与 `git diff --check`。
- `.gitattributes` 可固定文本行尾与二进制类型。

## 3. 生成文件

- `.uid`、`.import`、缓存目录、构建产物按项目规则处理。
- 不手改生成文件；清理后应能重建。
- 二进制证据（截图/录屏）单独命名，避免与构建产物混淆。

## 4. 并行 Git

- 同一仓库同一时间只允许一个 `git add/commit` 进程。
- 并行代理/终端要各自使用独立 worktree，不要共享 index。
- 看到 `index.lock` 先确认没有 Git 进程；不要直接删锁后继续提交。
- 提交前 `git status` 确认暂存区；并行操作后重新检查，不假设之前的暂存还在。
- 多仓库提交按仓库串行；不要并行 `git add -A`。

## 5. 提交前检查

- `git diff --check`：空白/行尾问题
- `git status --short`：是否混入用户未提交工作
- `git diff --stat`：是否整文件重写
- 编码/BOM：源码与文档
- 证据文件：命名/尺寸/是否需要入库

## 6. 失败处理

- 编码损坏：从版本库恢复，重新应用改动；不要在被损坏的文件上继续编辑。
- `index.lock`：确认进程结束后再清理；仍失败则停止并报告。
- 行尾噪声：先修 `.gitattributes`/编辑器设置，再提交内容变更。
- 部分仓库推送失败：只重试失败仓库，不重复提交已成功仓库。
