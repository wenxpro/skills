# Profile — Architecture

## 角色

| 角色 | 关注点 | 否决权 |
|---|---|---|
| 业务负责人 | 是否支撑业务目标、成本 | 价值不成立 |
| 架构师 | 边界、依赖、演进、一致性 | 架构不可持续 |
| 安全 | 权限、数据、攻击面 | 安全不可接受 |
| 运维 / SRE | 部署、监控、容量、回滚 | 无法稳定运行 |
| 开发 | 可实现、可测试、可维护 | 实现不可行 |
| QA | 验收、故障注入、回归 | 验收不足 |

## 必问

1. 这次架构变更的边界是什么？
2. 依赖方向是否清晰？有没有环？
3. 失败模式、降级、回滚是什么？
4. 数据迁移/兼容性怎么处理？
5. 监控、告警、SLO 是什么？
6. 什么情况下应该拒绝上线？

## 证据

- ADR
- 架构图
- 接口/数据约定
- 容量/性能测试
- 威胁模型
- 上线/回滚方案
