# Profile — Experience

## 角色

| 角色 | 关注点 | 否决权 |
|---|---|---|
| 新用户 | 能否找到开始、退出、返回 | 入口不可发现 |
| 回访用户 | 能否快速继续、重开、换配置 | 核心路径被菜单挡住 |
| UX | 层级、返回、焦点、暂停是否一致 | 导航不一致 |
| 技术负责人 | 状态所有权、生命周期、暂停作用域 | 状态边界不可维护 |
| QA | 每个表面、每条边是否可测试/可清理 | 关键流程不可验证 |

## 必问

1. 根入口是哪一个？是否只有一个？
2. 最多两层导航是否成立？有没有深层菜单？
3. 产品状态与局内/会话状态是否分离？
4. 每个表面是否有入口、退出、返回和 owner？
5. 每个模式是否有 Setup → Run → Result → Retry/Exit？
6. 暂停作用域是否写清？菜单会不会被业务暂停冻结？
7. 重开/退出是否清理节点、定时器、信号、缓存？
8. 延后项是否都有触发条件、成本和 owner？
9. 新用户能否在不解释的情况下找到开始和返回？
10. 这套拓扑能否支持下一个模式/入口，而不重做 Shell？

## 证据

- Experience Map
- 屏幕/导航决策
- 延后项清单
- 状态所有权表
- 关键流程验收种子

## 文档

体验架构由 `experience-architecture` skill 维护；本 profile 只负责角色与否决规则。
