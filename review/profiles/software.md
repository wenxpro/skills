# Profile — Software

## 角色

| 角色 | 关注点 | 否决权 |
|---|---|---|
| 用户 / 客户 | 是否解决真实问题、是否易用 | 需求不成立 |
| 产品 | 场景、范围、优先级、验收 | 价值不成立 |
| 技术负责人 | 架构、复杂度、维护、成本 | 技术不可行 |
| UX | 流程、信息层级、可访问性 | 可用性不成立 |
| PM | 时间、资源、依赖、上线窗口 | 超范围 |
| QA / 安全 | 可测试性、边界、权限、数据 | 验收/安全不足 |

## 必问

1. 这次变更解决谁的什么问题？
2. 成功/失败如何度量？
3. 回滚方案是什么？
4. 权限、数据、兼容性边界是什么？
5. 监控、告警、值班谁负责？
6. 哪些非目标明确不做？

## 证据

- PRD / RFC
- 接口/数据说明
- 测试计划
- 监控/回滚方案
- 安全/权限评审
