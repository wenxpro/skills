# 文档集审核规范（个人/团队风格标准）

本文件存放 `docs-audit` 中依赖具体风格、团队习惯与渲染环境的部分，其他团队可整体替换为本团队标准。`SKILL.md` 引用了本文件三个小节：翻译腔与术语、验证表述、mermaid 写法。

## 翻译腔与术语

判断标准：大陆技术书和文章里的自然说法，不是英文逐词翻译。常见翻译腔模式：

- 英文名词逐词直译（blast radius 直译成爆炸半径，应改为能力边界、影响范围这类自然说法）
- 生造组合词（把两个抽象词硬拼在一起，读起来不像人话），找到原英文词后用中文重写整句
- 反例要放过：「落点」在「权衡落点」「模式落点」里是自然用法（指具体应用位置），不机械替换

## 验证表述

结论的正确性不靠语气，靠验证链。四条约定：

1. **判断与事实分写**，事实带版本锚点，读者能自己复核
2. **结论写演进故事不写断言**：先怎样、后来为什么改、改成什么，前因后果自带验证
3. **反面验证优先**：别人踩过的坑（协议大改毁生态、被证伪的旧架构）比正面论证有力
4. **未验证的预测必须标注验证状态**：依据是什么、缺什么证据、有效期到哪。典型句式：「机制层已被验证（版本锚点），策略层没有公开实现，属于预测」

## mermaid 写法

- 节点文本用双引号包裹、`<br/>` 换行
- 虚线带文本箭头用 `-. 文本 .->`，文本内不要有反斜杠转义
- sequenceDiagram 的 alt/else/end 配对
- subgraph 嵌套合法
