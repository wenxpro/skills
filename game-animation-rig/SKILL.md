# 游戏动画与骨骼管线

目标：让动画表现服从**资产规则、玩法状态和接触帧**，而不是把问题归因于「模型不好看」。

本 skill 负责资产合同、重定向、地面接触、状态机与表现层映射；战斗数值用 `game-combat-model`，打击反馈用 `game-feel`，引擎工程用 `godot-game-runtime`。

## 何时使用

- 接入人形/Boss 动画、换骨架、换 mesh、换武器
- 动画错位：反向脚、反向剑、T-pose、滑步、浮空/穿地
- 重定向后动作变形、Hips 高度缺失、首尾不循环
- 需要设计移动/转身/侧移的表现层方案
- 需要把动画事件与玩法接触帧对齐

不适用：

- 战斗数值、攻击时间轴、TTK、克制预算 → `game-combat-model`
- hitstop、震屏、闪白、trail 的预算与验证 → `game-feel`
- Godot 工程配置、headless、音频总线 → `godot-game-runtime`
- UI token、组件、无障碍 → `ui-baseline`

## 行为

参考型 skill，无主动打断。用户要求接入/排查动画管线时使用。

## 核心规则

### 1. 先定资产合同，再谈动画

- 单位、朝向、原点、缩放、骨架命名、脚底接触点、武器挂点先写清。
- 资产前方与引擎前方不一致时，在**唯一适配层**修正；不要在多个脚本里各转一次。
- 非均匀缩放、骨骼全局缩放、独立 bone roll 是高风险项；先验证，再挂几何。
- 坐标/缩放不对时，IK、地面曲线、动画混合都是在错误坐标系上打补丁。

### 2. 玩法根与视觉根分离

- 玩法根负责碰撞、位移、朝向；视觉根负责模型朝向、倾斜、地面偏移。
- 默认关闭根运动；需要时单独轨道、单独验收。
- 视觉根的朝向/倾斜不能反向写回玩法根，否则攻击方向、相机、碰撞会漂移。
- 角色朝向、镜头朝向、移动输入方向三者要明确谁优先；锁定类游戏通常让根节点面向目标，侧移只改视觉表现。

### 3. 脚底接触是逐帧问题

- 每个角色提供 Foot/Toe 接触点；逐帧采样最低脚底。
- 不要只用出生时的一次全局 offset；按 clip + 时间做地面曲线，或逐帧 clamp。
- Hips Y 缺失时，先修资产/重定向；不要伪造 Hips Y 来掩盖问题。
- 脚底 clamp、IK、代理脚块只能解决表现，不改变碰撞体与玩法高度。
- 站立、走跑、起手/收招、倒地分别定义容差；阈值写进项目规范，不写进通用规则。

### 4. 重定向必须验证数据，不只看预览

- 每个 clip 检查：轨道数、关键帧数、首尾差、Hips 高度曲线、脚底最低点。
- 缺失 clip 必须显式 fallback；不允许静默 T-pose。
- 循环 clip 要同时设置资源 loop 与状态 loop；只设一处会停末帧。
- 插值类型、采样率、缩放轨道、重复命名都要进导入检查。
- 重定向后的武器骨骼/手骨朝向必须单独核对。

### 5. 状态机：玩法状态与动画状态分离

- 玩法状态决定「该播什么」；动画层决定「怎么播」。
- 状态名保持稳定；外部只通过适配层方法设置，不直接改内部节点。Godot 参数路径/工程集成由 `godot-game-runtime` 负责；本 skill 定义状态语义与资产规则。
- windup/strike/recovery 用自定义时间轴时，明确哪一段定格、哪一段播放、哪一段被玩法时长截断。
- 时间缩放/BlendTree 输出连接要可读回；没有输出连接的混合树会「状态在、姿势不动」。
- 同帧多请求要有优先级，避免攻击/受击/死亡互相覆盖。

### 6. 接触帧只有一个事实源

- 伤害/防御在接触事件结算；动画事件与玩法计时器只能有一个事实源。
- 视觉接触与规则接触要分别验证：规则用固定步长断言，视觉用定格/录屏。
- 动画混合、过渡、自定义时间轴都可能吞掉首尾帧；接触帧必须用审计证明。
- 浮动边界（计时器减到 0）要显式处理，避免固定步长下多算一帧。

### 7. 武器挂点与代理几何

- 武器原点在握把，轴向、长度、握把偏移写进资产说明。
- 优先用显式挂点/代理，而不是无条件 BoneAttachment；当骨架缩放/roll 不可信时，骨骼只提供位置，几何朝向由代码定义。
- 长武器要检查低位姿势的穿地；刀尖/枪尖做地面以上 clamp。
- 武器剪影是玩法信息的一部分：不同武器至少在一个轴上可区分，不能只靠颜色。

### 8. 移动/侧移/转身

- 先定本地前向轴；前进、后退、侧移分别用什么 clip 要写清。
- 步幅匹配：按实际速度 / clip 自然速度缩放播放，避免脚滑。
- 没有 strafe/turn clip 时，可以「根节点锁目标 + 视觉根偏航/侧倾」近似，但必须标明是近似，不冒充八方向资产。
- 原地转身用 stepping turn 时，播放速率与转向角度关联；转身不应产生位移。
- 侧移/转身的视觉偏移要在停止、攻击、格挡时回到中性。

### 9. 证据分层

- 静态 contact sheet 只能证明剪影/朝向；不能证明脚底、滑步、接触帧。
- 侧视/定格证明腿部与武器；固定步长断言证明接触时序；录屏/试玩证明连续观感。
- 每个修复至少留一张「修复前/修复后」或一条可复跑断言。
- 结论要写清「证明了什么、没证明什么」。

## 检查清单

- [ ] 资产单位、朝向、原点、缩放、骨架命名有书面合同
- [ ] 视觉根与玩法根职责分离，根运动默认关闭
- [ ] Foot/Toe 接触点逐帧采样，脚底不穿地/不浮空
- [ ] Hips Y 有数据或已记录缺失，不用全局 offset 伪造
- [ ] 每个 clip 检查轨道、首尾、脚底、武器骨
- [ ] 缺失 clip 有显式 fallback
- [ ] 循环 clip 资源与状态都设置 loop
- [ ] BlendTree 输出已连接，时间缩放可读回
- [ ] 接触事件只有一个事实源，固定步长可审计
- [ ] 武器握把/轴向/长度/穿地检查通过
- [ ] 前进/后退/侧移/转身的 clip 与朝向规则明确
- [ ] 近似方案（如无 strafe clip）已标注，不冒充正式资产
- [ ] 证据覆盖静态、时序、连续观感三层

## 输出

- 资产合同/重定向检查：`references/asset-contract.md`
- 常见失败模式：`references/failure-modes.md`
- 修正记录：现象 / 判断 / 修复 / 回写
- 需要数值/预算时交给 `game-combat-model` 或 `game-feel`

## 反模式

- 坐标/缩放没对齐就先加 IK/地面曲线
- 用全局 offset 代替逐帧脚底接触
- Hips Y 缺失却用视觉根硬补
- 骨骼 roll/缩放不可信还强行 BoneAttachment
- 只设状态 loop，不设资源 loop
- BlendTree 不接 output，误判为动画没加载
- 用静态截图证明滑步/接触帧
- 没有 strafe/turn clip 却声称八方向完成
- 把动画问题归因于「模型不好看」而不查资产合同

## 交接

- 战斗时间轴/数值/克制 → `game-combat-model`
- hitstop/震屏/闪白/trail → `game-feel`
- Godot 工程、CLI、AudioServer、导入 → `godot-game-runtime`
- 验证计划/证据层级 → `validation-design`
- 项目动画规范/验收 → `game-docs`

## 边界

- 不写具体项目的快照数值、clip 名、场景名
- 不替代战斗模型、反馈预算、引擎工程
- 不评价最终美术风格；只保证资产/状态/接触规则可验证
- 近似方案必须标注边界，不把 workaround 写成通用规则
